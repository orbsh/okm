# 集成边界：扩展类型与原语的对应

okm 只有三个原语：**有序前缀扫**（数据段 = 排序维度）、**函数索引**（数据段 = 单行派生值，写入时预计算）、**双向边**（关系一等公民）。本文回答：FTS、向量、图算法这些"高级能力"如何落在这三个原语上（对应 `okm-ngram` / `okm-vector` / `okm-graph` 三个集成 crate），以及——同样重要——哪些扩展落不进来，为什么。

## 核心论点

三类能力都不需要新的存储原语：

```text
FTS    = 多值函数索引（n-gram/token → N 条 entry）+ 调用方 BM25 精排
向量   = 单值函数索引（定宽 embedding 字节串）+ 量化桶前缀扫 + 边条目做 ANN 图
图算法 = 边条目（neighbors = 一次前缀扫）+ 有序流折叠（label propagation / PageRank）
```

算法层（打分、迭代、收敛）全部在集成 crate 或调用方；okm-core 只保证「有序流」这一件事。判断一个新扩展类型是否值得做，就看它是否只是**原语之上的配方**——配方进集成 crate，新原语进核心。

## 预计算的两层分界

预计算经常被笼统提及，实际是两个不同的东西：

**单行派生——就是函数索引。** `lower(name)`、`hour(ts)`、embedding、分词：写入时算一次，读取时零计算。func 的本质是把读侧成本搬到写侧。代价对称：每次 put/delete 付一次函数调用（多值时 N 次），换读路径永远是纯扫描。

**跨行聚合——不是 func，是 value 侧的计数器模式。** func 的签名是 `fn(&Row)`，只看得见一行；rollup（每小时计数）、精确计数器、滑动平均是跨行的。它们的落点是 entry value 的**读-改-写**——而这是与索引条目纪律相反的原语：

- 索引 entry：append-only，随行生灭（delete 同一函数生成待删集合，永不悬挂）；
- 计数 entry：可变 value，有独立生命周期（行删了计数还在，或需要墓碑逻辑）。

这意味着跨行预计算是**第四个原语**（可变聚合 entry）。okm-core 对它的立场是两层拆分：**核心仍不内置聚合语义**——不提供任何内建计数器/求和类型，也不解决分布式累加协议；但机械部分由辅助设施提供——`#[kv_aggregate(Logic { group(a,b) })]` 声明 + `AggregateLogic`（用户实现 fold/unfold 与 Acc 编码）+ 写入路径的读-改-写 hook（put 时 fold、delete 时 unfold）。可逆性（`unfold(fold(a,x)) = a`）是使用者的契约，不可逆聚合（median、distinct）不适用；okm-core 不做零值回收，组空了 entry 仍在。用法见建模文档「跨行预聚合」一节。

并发语义的边界没有变：单写者引擎下 hook 是安全的读-改-写；多写者/分布式累加协议仍然超出「有序字节流」模型，真需要时答案依旧是旁边放真正的 OLAP/流系统。近似计数（UV、热词）优先退化为「entry 存在即计 1」+ 扫区间数条数。

## 能落的扩展类型（已有或可成 crate）

- **时序/聚合**——时间戳 BE 定宽进数据段（字节序 = 时间序），前缀扫 = 时间窗口；`group_by` 折叠出 rollup。零新代码，是建模手段不是 crate。
- **排行榜**——分数定宽 BE + `Reverse<T>` 处理降序，主键尾段去重；`scan` 即按分取区间。同样零新代码。
- **自动补全**——字段直接作数据段，前缀扫即补全。一个 `fields(...)` 声明，不值得任何代码。
- **地理**——Geohash 字符串作数据段，前缀扫 = 空间范围（Geohash 前缀就是矩形）。本质与 ngram 同构（字符串前缀），可以并进未来需求再立 crate。

## 落不进来的（明确不做）

- **hash join / 无序 join 加速**——join key 不是排序维度是建模缺口，声明索引让流重新有序；`okm-query::merge_join` 是唯一答案。
- **流式订阅 / CDC**——没有 tail 扫原语，属引擎层（fjall watch / slatedb invalidate），不该在模型层仿造。
- **分布式累加协议**——单写者下 `#[kv_aggregate]` 的读-改-写 hook 是安全的；多写者竞态/分布式计数器协议仍超出「有序字节流」模型，属旁边的 OLAP/流系统。
- **通用二级缓存**——缓存失效策略是应用逻辑；okm-core 条目生灭绑定声明，没有挂失效钩子的位置。

## 集成 crate 的边界纪律

`okm-ngram` / `okm-vector` / `okm-graph` 的共同约束：

1. **零存储职责**——不建自己的表结构、不绕过 `KvIndex`/`EdgeEncode`，一切数据走声明条目；
2. **算法可替换**——crate 给的是最小可用配方（ngram+BM25、桶扫+精排、LP+PageRank），更重的方案（Tantivy、arroy/HNSW、Louvain）由调用方按同一条目布局自接；
3. **依赖最小**——能不引外部依赖就不引；确需引（如 ANN 库）时挂在自己的 crate，不进核心。
