# ADR-0030：slot——固定面一字节，计数族两字节

**状态**：已接受（2026-10-17）——已实现。slot 的自定界在 `index::slot` / `write_slot` 里
（family nibble 非零 = 两字节，为零 = 一字节），上限是 assert 而不是掩码，在用的计数族是 0x1–0x4。
**日期**：2026-10-17
**英文版**：[0030-slot-fixed-faces-and-counting-families.md](0030-slot-fixed-faces-and-counting-families.md)
**取代**：ADR-0016 的段表（4 字节头对计数族继续有效；slot 的宽度现在由族决定）
**依赖**：ADR-0005（索引 slot）、ADR-0012（对象模式与字段名词汇表）、ADR-0016（头与段）、ADR-0017（图面）、ADR-0032（声明式词汇表）、ADR-0041（图面携带两端）

## 背景

今天每条条目的 key 都付 2 字节 slot——`[ns 2B][slot 2B]`，4 bit 段号加 12 bit 计数（ADR-0016）。那 12 位是按容量余量买的：每段 4096，声明索引容量从 240 提到 4096。

对着真实的消费者量一遍：在用的 12 张固定面**全是单张面**——主表、obj 动态段、字段名词汇表的两个方向、谓词词汇表的两个方向、图的四张面、向量快照、表元信息。它们的计数位是常量（段 0x0 内的面是 0/1/2/3，图面恒 1），不携带任何信息，却在每一条这种 key 上占一个字节。

这些面还把同一类东西写成两种形态：0x06 以下的面是段 0x0 里的计数位（pre-0016 扁平角色表的化石——当时角色 0–15 共用一个编号空间），而图面各占一整段（`0x4001`…`0x8001`，计数位钉在 1）。「一张面一个号」才是统一的规则。

付这个字节的恰好是存储里数量最多的条目：主表（每个文档一条、每条边一条）与图的遍历面（一个边集合数千条）。ADR-0017 §2 为一个引用上的一字节算了约 5% 并认真权衡过；这里这一字节落在每一条主键、每一条遍历条目上。

## 决策

### 1. slot 自定界——宽度由族决定

slot 的首字节自己说明后面还跟不跟计数字节：

```text
固定面        首字节高半字节 = 0     slot = 1 字节   [ns 2B][0x0F]
计数族        首字节高半字节 ≠ 0     slot = 2 字节   [ns 2B][0x1n][nn]
                                                    计数 = (n << 8) | nn
```

所以每一张固定面——主表、动态段、两本词汇表、图的四张面、向量快照、表元信息——都只读一个字节；真正带实例的两个计数族保留两个字节。

实现上宽度跟着 slot 的**值**走：值 ≤ 0x0F 写一个字节，其余写两个大端字节（族号没有 0，所以不会有别的值落进 0x00–0x0F）。`write_slot` 断言这条规则、`slot_len` 给出宽度——两者与常量同住在 `okm-core::model::index`，于是每个拼键的地方都以同一方式写 slot。

### 2. 固定面表（1 字节，16 个号）

```text
0x00  主表              文档集合或边集合
0x01  obj 动态段        [ns][0x01][主键]                             value = toc_len | blocks | values（[动态段](../internals/dynamic-segment.zh-CN.md)）
0x02  字段名词汇表      [ns][0x02][field-id]                         → 名字
0x03  字段名词汇表      [ns][0x03][名字]                             → field-id
0x04  谓词词汇表        [ns][0x04][predicate_id]                     → 名字
0x05  谓词词汇表        [ns][0x05][名字]                             → predicate_id
0x06  图 出边           [ns][0x06][src 引用][dst 引用][edge_id]
0x07  图 入边           [ns][0x07][dst 引用][src 引用][edge_id]
0x08  图 谓词+出        [ns][0x08][predicate_id][src 引用][dst 引用][edge_id]
0x09  图 谓词+入        [ns][0x09][predicate_id][dst 引用][src 引用][edge_id]
0x0A  簇 簇行         [ns][0x0A][kind][簇号]（值 = parent_id + 载荷）
0x0B  簇 边成员       [ns][0x0B][kind][簇号][边号]（ADR-0066）
0x0C  簇 子簇索引     [ns][0x0C][kind][父簇号][子簇号]（派生，可重建）
0x0E  Extension           [ns][0x0E][子类]…   子类各自定契约（0x01 向量快照，可丢）
0x0F  表元信息          [ns][0x0F]                   → 名字 → 字节的映射（ADR-0043）
```

表按**角色**排——词汇在它所服务的面之前；**编号**才是机制。0x0F 刻意取最高位：`slot <= 0x0F` 就是一字节/两字节的定界位，元信息面正坐在边界上，后加的固定面挤不掉它。

**谓词词汇表有了自己的一对固定面（0x04/0x05）。** 集合在字段名之外的 token 词汇——图的谓词、节点集合的 kind token——不等于载荷的字段名词汇表（0x02/0x03）：列出它就是扫一次 0x04 前缀，而两个分配用的 cache 再也不可能把同一个 id 发给两个名字（ADR-0017 §3）。图的声明属性面仍是普通声明索引，族 0x3，住在边集合自己的 ns 里。

### 3. 计数族（2 字节，12 bit 计数）

```text
0x1nnn  词汇表      label → id；计数 = 词表自己的编号（从 1 起）
0x2nnn  词汇表      id → label；同一个计数，另一个方向/族（分配游标在本面的裸前缀上）
0x3nnn  声明索引    计数 = 声明序（从 1 起 → 每集合 4095 条）
0x4nnn  reduce      计数 = 声明序，独立配额（4095）
0x5nnn  前导面      计数 = 声明序（从 1 起 → 每集合 4095 条，ADR-0054）
段 0x6–0x0F         空着（10 段）
```

计数宽度不变：一个集合仍是 4095 条声明索引、4095 条 reduce，与以前一样。

### 4. 定界是关于字节的事实，不是查表

`b & 0xF0 == 0` 读 1 字节 slot，否则读 2 字节。两个空间在首字节上不可能重叠（0x00–0x0F 与 ≥0x10），所以按族拼前缀扫描天然精确，不需要查段表：`[ns][0x07]` 不可能命中计数族，`[ns][0x1n][nn]` 不可能命中固定面。定界是字节自身的属性、不是一张要维护的名单——与 ns 转义字节（`0xFF`，ADR-0012）和自描述端点引用（ADR-0017 §2）同一立场。

### 5. 词汇

「段号」此后只指计数族的号（它们首字节的高半字节）。单张面的族叫**固定面号**：一字节，没有计数位，没有东西可枚举。

## 考虑过的替代

- **扁平 1 字节 slot，族按第一级范围切**（固定面在前，索引/reduce 各占一段范围）。否决：第一级按范围切，等于预设各族的增长比例。pre-0016 那张表的"两头向中间增长"缓冲带（固定角色自 0 上行、边钉在 14/15 下行、4–13 是未划分的带）只能界定两个类别——出现第三个时边界要等两头相遇才知道。它还会把真正需要计数的族的上限锁死在切分剩下的范围里。
- **只做提级，不改宽度**（固定面各自成段，全部条目仍 2 字节 slot）。否决：它要重编计数族的号（索引/reduce 挪到 0x9/0xA，逼出一次迁移），同时仍在数量最多的条目上付着那个死掉的计数字节。它只换来词汇的一致，代价却是更重的迁移。
- **挪动定界位来扩固定面空间**（例如首字节 < 0x80 即 1 字节：128 个固定面、8 个计数族）。今天不取：16 个固定面用了 12 个，15 个计数族用了 4 个。记作增长路径——唯一的旋钮是 k：首字节高 k 位为 0 → 固定面 `2^(8−k)` 个、计数族 `2^k − 1` 个。
- **计数族用 3 字节 slot**（族字节 + 完整 u16 计数，如 `0x01 00 01`）。否决：为没人用的计数余量把索引条目做得比今天更长。

## 边界

- **固定面不带计数位。** 若今天只有一张面的族日后需要实例，它要变成计数族（从 0x6–0x0F 领一段），而不是拿自己的固定面号去装子类。新的单张面种类领下一个空闲固定面号（核心带只剩 `0x0D` 一个空号；新的行型进 `0x0E` Extension，带内用子类再分）。
- **计数只有一种宽度，12 位。** 没有按族定制的计数宽度；族字节的低半字节属于计数。
- **声明索引与 reduce 都是每集合 4095 条**（12 位计数的 4096 个值里 0 号保留），不是 4096——4096 会撞进下一个族的段。
- **上限在「算号码的地方」被检查。** `index::slot(family, counter)` 对两半都做断言，而不是把它们掩掉：它是 `const fn`，坏的声明期常量在编译期就失败；derive 的 `declared_slot` 在展开期跑它的界；运行期调用方得到同样的拒绝。被掩掉的值不是「一个错的数字」，而是**另一个族的合法槽位**——`0x3FFF + 1 = 0x4001` 正是 reduce 族，第 4096 条索引会被写进 reduce 段并被当作 reduce 行读回；族号过 `0xF` 则会绕进固定面空间。
- 头不再全族统一（3 或 4 字节）。族在每个拼装点都是编译期常量，所以前缀拼接与主键尾段切片仍是静态算术，不做运行期探测。

**面级单值不是号段。** 一张面可以放**一个**元数据值，键就是裸面前缀 `[ns][slot]`、不带任何后缀。成立的条件只有一条：该面所有真实条目的后缀长度恒 ≥ 1——于是零长度后缀在编码层面无法产生，相撞就**靠长度**被排除，不靠保留某个 id 或某个标签。规则对所有"一面一值"的元数据成立（版本戳、水位），两个反例也是规则的一部分：label 面（空串是合法标签）与无分组 reduce 面（它的条目键**就是**裸前缀）都不能放。读者按后缀长度区分两者，而定宽解码器本来就会拒绝长度不符。表元信息面（0x0F）与每本词汇表的分配游标就是在用的两个单值。

每一对声明式词汇表都有一条游标，键是推导出来的、不是编号出来的：游标就是 `[ns][id 面]`，所以导出的 slot map（`SlotMap`）只列每对词汇表的两张面、根本不列游标——宿主侧自行分配 id 的写入方必须用 `obj_vocab::cursor_key` 从 id 面号拼键，并在花掉它的那些条目的**同一个 commit** 里递增。这是本约定唯一离开 schema 的地方，写在这里的原因也正是替代方案：给游标一个 slot 号会让它变成一张自成一体的面，而本 ADR 的"不设号段"规则存在的目的就是不让这种事发生。

## 后果

- **key 格式变更，发布前窗口。** 主表与每一张固定面各少一个字节；动态段与两本词汇表换号（0x0001→0x01、0x0002/0x0003→0x02/0x03）；图面去掉计数、落在 0x06–0x09，向量快照当时在 0x0A（2026-11-12 移到 0x0E：缓存面排到最远，核心面保持连续）。索引/reduce 的字节一个不变——0x3nnn 与 0x4nnn，就是绑定侧传入的 slot 值。无外部消费者（PLAN），所以一次重建即可覆盖：派生条目从文档重建，动态段与词汇表随同一次重建。
- `SlotMap`（schema 导出）保持 `u16` 字段——值现在是固定面的 0x00–0x0F 与计数族的 0x1nnn–0x5nnn，宽度由值本身蕴含。绑定侧传的 slot 参数不变。
- ADR-0016 的段表被取代；它的头宽决策对计数族继续有效。
- docs/internals/key-layout 与 slot-mechanism 承载布局表，那里的机制文字与本决策成为一对。
