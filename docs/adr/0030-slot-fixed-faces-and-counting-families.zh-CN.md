# ADR-0030：slot——固定面一字节，计数族两字节

**状态**：已接受（2026-10-17）——设计定案；实现待做，见「后果」
**日期**：2026-10-17
**英文版**：[0030-slot-fixed-faces-and-counting-families.md](0030-slot-fixed-faces-and-counting-families.md)
**取代**：ADR-0016 的段表（4 字节头对计数族继续有效；slot 的宽度现在由族决定）
**依赖**：ADR-0005（索引 slot）、ADR-0012（对象模式与字段名词汇表）、ADR-0016（头与段）、ADR-0017（图面）

## 背景

今天每条条目的 key 都付 2 字节 slot——`[ns 2B][slot 2B]`，4 bit 段号加 12 bit 计数（ADR-0016）。那 12 位是按容量余量买的：每段 4096，声明索引容量从 240 提到 4096。

对着真实的消费者量一遍：在用的 12 个 slot 里有 **9 个是单张面**——主表、obj 动态段、字段名词汇表的两个方向、图边的五张面（2026-10-17 更新：图的谓词词汇表又占掉两个固定面——0x04/0x05——所以今天单张面是 12 个）。它们的计数位是常量（文档自身那一桶是 0/1/2/3，图面恒 1），不携带任何信息，却在每一条这种 key 上占一个字节。

这 9 个还把同一类东西写成两种形态：四个文档自身面是段 0x0 里的计数位（pre-0016 扁平角色表的化石——当时角色 0–15 共用一个编号空间），而图边的五张面各占一整段（`0x4001`…`0x8001`，计数位钉在 1）。「一张面一个号」才是统一的规则。

付这个字节的恰好是存储里数量最多的条目：主表（每个文档一条、每条边一条）与图的遍历面（0x07–0x0A，一个边集合数千条）。ADR-0017 §2 为一个引用上的一字节算了约 5% 并认真权衡过；这里这一字节落在每一条主键、每一条遍历条目上。

## 决策

### 1. slot 自定界——宽度由族决定

slot 的首字节自己说明后面还跟不跟计数字节：

```text
固定面        首字节高半字节 = 0     slot = 1 字节   [ns 2B][0x0F]
计数族        首字节高半字节 ≠ 0     slot = 2 字节   [ns 2B][0x1n][nn]
                                                    计数 = (n << 8) | nn
```

二进制对照，在用的 12 个 slot，前 → 后：

```text
                        今天                       slot 字节数   之后            十六进制
0x0000 主表              0000 0000 0000 0000       2 → 1        0000 0000       00
0x0001 obj 动态段        0000 0000 0000 0001       2 → 1        0000 0001       01
0x0002 词汇表 号→名        0000 0000 0000 0010       2 → 1        0000 0010       02
0x0003 词汇表 名→号        0000 0000 0000 0011       2 → 1        0000 0011       03
0x1001 索引第1条         0001 0000 0000 0001       2 → 2        0001 0000 0000 0001   10 01
0x1002 索引第2条         0001 0000 0000 0010       2 → 2        0001 0000 0000 0010   10 02
0x2001 reduce第1条       0010 0000 0000 0001       2 → 2        0010 0000 0000 0001   20 01
0x3002 junction(n=1,dir=0) 0011 0000 0000 0010     2 → 2        0011 0000 0000 0010   30 02
0x4001 边 kind 索引      0100 0000 0000 0001       2 → 1        0000 0100       04
0x5001 边 出边           0101 0000 0000 0001       2 → 1        0000 0101       05
0x6001 边 入边           0110 0000 0000 0001       2 → 1        0000 0110       06
0x7001 边 kind+出        0111 0000 0000 0001       2 → 1        0000 0111       07
0x8001 边 kind+入        1000 0000 0000 0001       2 → 1        0000 1000       08
```

右边九行各读 1 字节——它们的高半字节就是定界位；三个计数族与今天的字节完全一致。（2026-10-17 更新：图的面后来又挪了一次——0x06–0x0A——谓词词汇表占了 0x04/0x05，见 ADR-0017 §3。下面这九张是**迁移映射**的记录；今天的分配以 §2 的表为准。）

实现上宽度跟着 slot 的**值**走：值 ≤ 0x0F 写一个字节，其余写两个大端字节（族号没有 0，所以不会有别的值落进 0x00–0x0F）。`write_slot` 断言这条规则、`slot_len` 给出宽度——两者与常量同住在 `okm-core::model::index`，于是每个拼键的地方都以同一方式写 slot。

### 2. 固定面表（1 字节，16 个号）

```text
0x00  主表              文档集合或边集合
0x01  obj 动态段        [ns][0x01][主键]                             value = nTLV 帧
0x02  字段名词汇表      [ns][0x02][field-id]                         → 名字
0x03  字段名词汇表      [ns][0x03][名字]                             → field-id
0x04  谓词词汇表        [ns][0x04][predicate_id]                     → 名字
0x05  谓词词汇表        [ns][0x05][名字]                             → predicate_id
0x06  图 谓词索引       [ns][0x06][predicate_id][edge_id]
0x07  图 出边           [ns][0x07][src NodeRef][edge_id]
0x08  图 入边           [ns][0x08][dst NodeRef][edge_id]
0x09  图 谓词+出        [ns][0x09][predicate_id][src 引用][edge_id]
0x0A  图 谓词+入        [ns][0x0A][predicate_id][dst 引用][edge_id]
0x0B  向量索引快照      [ns][0x0B][shard u16 BE]   → 建好的图（okm-vector 缓存）
0x0C–0x0F                   留给将来的固定面
（2026-10-17 更新：表按**角色**排——词汇在它所服务的面之前；**编号**才是机制。）
```

**2026-10-17 更新：谓词词汇表有了自己的一对固定面（0x04/0x05）。** 集合在字段名之外的 token 词汇——图的谓词、节点集合的 kind token——不再等于载荷的字段名词汇表（0x02/0x03）：列出它就是扫一次 0x04 前缀，而两个分配用的 cache 再也不可能把同一个 id 发给两个名字（ADR-0017 §3）。图的声明属性面仍是普通声明索引，族 0x1，住在边集合自己的 ns 里。

### 3. 计数族（2 字节，12 bit 计数，号码不变）

```text
0x1nnn  词汇表     label → id；计数 = 词表自己的编号（从 1 起）
0x2nnn  词汇表     id → label；同一个计数，另一个方向/族（分配游标在本面的裸前缀上）
0x3nnn  声明索引   计数 = 声明序（从 1 起 → 每集合 4095 条）
0x4nnn  reduce     计数 = 声明序，独立配额（4095）
0x5nnn  junction   计数 = 区分号 << 1 | 方向；区分号 11 位 → 每端点对 2048 个
段 0x6–0x0F        空着（10 段）
```

这些号码一个不动，计数宽度也不动：一个集合仍是 4095 条声明索引、4095 条 reduce、2048 个 junction 区分号，与今天一样。

**面级单值不是号段。** 一张面可以放**一个**元数据值，键就是裸面前缀 `[ns][slot]`、不带任何后缀。
成立的条件只有一条：该面所有真实条目的后缀长度恒 ≥ 1——于是零长度后缀在编码层面无法产生，
相撞就**靠长度**被排除，不靠保留某个 id 或某个标签。规则对所有"一面一值"的元数据成立
（版本戳、水位），两个反例也是规则的一部分：label 面（空串是合法标签）与无分组 reduce 面
（它的条目键**就是**裸前缀）都不能放。读者按后缀长度区分两者，而定宽解码器本来就会拒绝长度不符。

**每一对词汇表都有一条游标，键是推导出来的、不是编号出来的。** 游标就是 `[ns][id 面]`，
所以导出的 slot map（`SlotMap`）只列每对词汇表的两张面、根本不列游标——宿主侧自行分配 id 的写入方
必须用 `obj_vocab::cursor_key` 从 id 面号拼键，并在花掉它的那些条目的**同一个 commit** 里递增。
这是本约定唯一离开 schema 的地方，写在这里的原因也正是替代方案：给游标一个 slot 号会让它变成
一张自成一体的面，而本 ADR 的"不设号段"规则存在的目的就是不让这种事发生。

### 4. 定界是关于字节的事实，不是查表

`b & 0xF0 == 0` 读 1 字节 slot，否则读 2 字节。两个空间在首字节上不可能重叠（0x00–0x0F 与 ≥0x10），所以按族拼前缀扫描天然精确，不需要查段表：`[ns][0x07]` 不可能命中计数族，`[ns][0x1n][nn]` 不可能命中固定面。定界是字节自身的属性、不是一张要维护的名单——与 ns 转义字节（`0xFF`，ADR-0012）和自描述端点引用（ADR-0017 §2）同一立场。

### 5. 词汇

「段号」此后只指计数族的号（它们首字节的高半字节）。单张面的族叫**固定面号**：一字节，没有计数位，没有东西可枚举。

## 考虑过的替代

- **扁平 1 字节 slot，族按第一级范围切**（固定面在前，索引/reduce/junction 各占一段范围）。否决：第一级按范围切，等于预设各族的增长比例。pre-0016 那张表的"两头向中间增长"缓冲带（固定角色自 0 上行、边钉在 14/15 下行、4–13 是未划分的带）只能界定两个类别——出现第三个时边界要等两头相遇才知道。它还会把真正需要计数的族的上限锁死在切分剩下的范围里。
- **只做提级，不改宽度**（固定面各自成段，全部条目仍 2 字节 slot）。否决：它要重编计数族的号（索引/reduce/junction 挪到 0x9/0xA/0xB，逼出一次 junction 迁移），同时仍在数量最多的条目上付着那个死掉的计数字节。它只换来词汇的一致，代价却是更重的迁移。
- **挪动定界位来扩固定面空间**（例如首字节 < 0x80 即 1 字节：128 个固定面、8 个计数族）。今天不取：16 个固定面用了 12 个，15 个计数族用了 3 个。记作增长路径——唯一的旋钮是 k：首字节高 k 位为 0 → 固定面 `2^(8−k)` 个、计数族 `2^k − 1` 个。
- **计数族用 3 字节 slot**（族字节 + 完整 u16 计数，如 `0x01 00 01`）。否决：为没人用的计数余量把索引条目做得比今天更长。

## 边界

- **固定面不带计数位。** 若今天只有一张面的族日后需要实例，它要变成计数族（从 0x4–0x0F 领一段），而不是拿自己的固定面号去装子类。新的单张面种类领下一个空闲固定面号（余 5 个）。
- **计数只有一种宽度，12 位。** 没有按族定制的计数宽度；族字节的低半字节属于计数。
- **上限措辞修正**：声明索引与 reduce 都是**每集合 4095 条**（12 位计数的 4096 个值里 0 号保留），不是 4096。旧文写 4096 会撞进下一个族的段。
- 头不再全族统一（3 或 4 字节）。族在每个拼装点都是编译期常量，所以前缀拼接与主键尾段切片仍是静态算术，不做运行期探测。

## 后果

- **key 格式变更，发布前窗口。** 主表与图的五张面各少一个字节；动态段与两本词汇表换号（0x0001→0x01、0x0002/0x0003→0x02/0x03）；图面去掉计数（0x4001–0x8001 → 0x06–0x0A）。索引/reduce/junction 的字节一个不变——包括 MODELING 里那两条 junction 字节断言，和绑定侧传入的 slot 值（0x1001/0x1002/0x2001）。无外部消费者（PLAN），所以一次重建即可覆盖：派生条目从文档重建，动态段与词汇表随同一次重建。
- `SlotMap`（schema 导出）保持 `u16` 字段——值现在是固定面的 0x00–0x0A 与计数族的 0x1nnn / 0x2nnn / 0x3nnn，宽度由值本身蕴含。绑定侧传的 slot 参数不变。
- ADR-0016 的段表被取代；它的头宽决策对计数族继续有效，它的 junction 落位部分原样成立。
- docs/internals/key-layout 与 slot-mechanism 承载布局表，那里的机制文字与本决策成为一对。

## Update 2026-10-24：上限在「算号码的地方」被检查

此前本 ADR 里的三个上限（4095 条索引、4095 条 reduce、2048 个 junction 区分号）只是文字：
每一个**拼出** slot 的地方都把越界的部分掩掉了。`index::slot(family, counter)` 写的是
`(family << 12) | (counter & 0x0FFF)`，derive 直接发 `DECLARED_SLOT_BASE + n` 不设界，
`KvJunction::dir_slot` 用 `0x07FF` 掩区分号。被掩掉的值不是「一个错的数字」，而是**另一个族的
合法槽位**：`0x3FFF + 1 = 0x4001` 正是 reduce 族，第 4096 条索引会被写进 reduce 段并被当作
reduce 行读回；族号过 `0xF` 则会绕进固定面空间。

三处现在都是拒绝而不是掩码——号码是声明期常量的地方在编译期拒绝（`slot` 是 `const fn`；
derive 的 `declared_slot` 与 `#[ok_junction(n)]` 校验在展开期跑），其余在运行期（`dir_slot`）。
上限本身没变，消失的只是「静默落到隔壁槽位」这条路。
