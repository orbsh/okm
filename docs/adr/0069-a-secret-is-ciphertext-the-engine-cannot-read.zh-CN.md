# 0069 — 秘密以密文存储，引擎不持密钥

状态：2026-11-17 裁决并落地。给 `okm-core` 加一个字段拼写、给 derive 加一个属性；不动任何键布局与值布局。

## 背景

应用必须保存**能读回来**的凭据：一个 API token、一个要重放给交换机的设备口令、一个 TOTP seed。丢了就丢账号，摘要没法重放。所以它们是加密存的，而本 ADR 要定的是那把钥匙站在边界的哪一侧。

今天这个引擎里有三处泄漏是**默认开着**的：

1. **字段可以被索引。** `#[ok_index(fields(…))]` 把字段的编码值写进**索引条目的键**（`KvIndex::entry_key`，`okm-core/src/model/index.rs`），`includes` 还要写进条目值。一个被索引的秘密就是第二份副本——有序、可枚举，而且会被该索引上的每一次范围扫描翻出来。
2. **字段会被导出。** 湖桥把每个声明字段变成一列 parquet（`okm-lake/src/bridge.rs` 的 `build_batch`），秘密就这样长成一列离开存储。
3. **字段会被打印。** `Debug` 是派生的，一次 `dbg!(row)` 或一个 `tracing` 字段，明文就进了日志。

单独看，这三件事都不是错误——那就是字段的正常行为。它们只对一种字段是错的。

## 裁决

**1. 秘密由应用加密，okm 只存密文。** 线上就是 `FieldType::Bytes`——`Bytes` 早已在用的那条变长 TLV 帧。不加字段类型、不动键布局和值布局、不升布局 generation（ADR-0042）。

**2. `Secret` 是一个类型，护栏挂在它身上。** `okm_value::Secret` 是同一串字节的 newtype，只差一处：`Debug` 打 `Secret(<redacted>, N bytes)`。它是唯一携带秘密语义的拼写，所以下面几条是**类型的属性**，不是文档里一句"请注意"，让下一个字段去违反。

**3. 秘密不能建索引，而且这件事是编译错误。** `#[ok_index(fields(…))]` 指向 `Secret` 字段、以及把该类型用作 key-prefix 字段，都由 derive 直接拒绝，不是运行期。理由就是 (1)：索引是一份排好序的副本，而排好序的秘密就是秘密本身。

**4. 导出默认写密文，`#[ok_redact]` 改为写 null。** 密文是有用的默认值——客户侧要解密，密钥轮换要对已有密文重新封装。抹除按字段、且必须显式声明，因为"一列悄悄消失"比"一列是 null"难发现得多。

**5. 引擎不持密钥。** 没有 KEK、没有 DEK、没有 KMS 客户端、`okm-core` 里没有加密依赖。信任边界就是进程：应用能解开的，引擎同样能解开，把钥匙搬进引擎不换任何东西。

## 后果

- 算法与密钥材料归应用：XChaCha20-Poly1305 或 AES-GCM，AAD 绑 `ns ‖ pkey ‖ 字段名`。绑上行身份意味着把一段密文搬到另一行会解不开——防跨租户复制粘贴最便宜的手段，与该面布局遵循的规则同源（`[ns][slot]` 不是装饰）。
- 密钥轮换与 crypto-shredding 归应用：重加密那些行，或者丢掉钥匙让密文作废。引擎没有可轮换的东西。
- changelog 像搬任何值一样搬密文，replay 原样复制——replay 路径上不需要密钥（这与"引擎持钥"形态相反：那一形态里 replay 必须逐条解开再重封）。
- 秘密字段不能排序、范围查、分组。这正是目的；关于凭据的查询走的是别的数据——所有者 id、租户、标签——永远不走秘密本身。
- 口令**验证**不在本 ADR 范围内，且不需要改动：口令存成 Argon2id 摘要（PHC 串），那是设计上就公开的，不需要加密——只需要同一条"不许索引"，而把它存成 `Secret` 就自然满足。

## 被否

- **引擎内的信封加密（每 ns 一把 DEK）。** 只有在"密钥不能留在应用进程里"或"删钥即销毁一整租户"是需求时才值得。代价是整条链：在编解码边界封（两个持久化写者——引擎与 changelog 帧）、每一条读路径、replay、导出、轮换，以及一个持钥的 store（崩溃转储会泄漏）。"存个密码"买不起这些。
- **确定性加密 + 索引，做等值查询。** 索引键里的确定性密文**就是**拿秘密当查找键：在它上面做等值就是枚举，而这正是加密要防的泄漏。SIV 不改变这一点——泄漏是"查询能答"，不是原语的问题。所以等值被否掉的理由与范围相同，不是附带。
- **把口令存成可逆密文。** 验证从不需要明文，可逆形态只扩大攻击面。
- **用整卷/整库加密来满足这个需求。** 那是文件系统的事（LUKS、fscrypt），且彼此正交：它保护一块被偷走的盘，不保护一次查询、一次导出、一行日志。

## 落地要付的测试

- 一个 `Secret` 字段与它的 `Bytes` 孪生字段**逐字节**相等地往返（裁决 1 的布局主张）。
- 持秘密的行的 `Debug` 输出里不含它的任何明文字节。
- `#[ok_index(fields(secret))]` 与把 `Secret` 当键字段都是编译错误（`okm-core/tests/compilefail/`）。
- 湖桥对秘密列写密文、`#[ok_redact]` 下写 null，且该列仍然存在。
