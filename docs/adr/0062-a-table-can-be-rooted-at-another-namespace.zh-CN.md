# ADR-0062：一张表可以植根于另一个命名空间

日期：2026-11-11
状态：已裁决并落地 2026-11-11

## 1. 背景

还原有一件扫库做不到的事：把湖里的一张表放到它声明里的 ns 之外。拥有目标的应用自己建一个空 ns，要求把行落在那儿（k10r ADR-0015：部分导入、数据迁移、分析类应用的交接），而湖里的表仍保持发布时的名字。

ns 不是 store 句柄的属性——它是键头的第一个字段 `[part][ns 2B][…]`，而 `Collection` 的每个动词都只经由一个函数 `header()` 触达键。所以问题从来不是「怎么写到另一个 ns 下」，而是「那 2 个字节归谁」。

## 2. 裁决：句柄上的一个字段

`Collection` 带 `ns_override: Option<u16>`。`with_ns(store, ns)` 构造一个设好它的句柄，`rebased(&self, ns)` 返回同一个引擎上设好它的句柄，`header()` 前置 `ns.to_be_bytes()` 而不是声明里的 `NS_PREFIX`。`ns()` 回答生效的命名空间；对根本不带 ns 字段的声明（部分测试文档如此）返回 `None`。

`Graph` 得到同一个字段（`[u8; 2]`）、同样两个构造器，外加 `has_edges()`。图必须**整体**搬——节点、边、面、社区编号——因为边的端点是 `[ns 2B]` 的引用，指向节点表：边被搬到新 ns 而节点留在原地，边就指向空气，而读者区分不出这和一条悬挂行。

`has_edges()` 是给还原的第一个问题用的（这个 ns 是不是没人用过？）。节点与边共用一个 ns，所以「这里什么都没有」不是只问节点表就能答的。

## 3. 随之移动的东西

- **`header()` 对外公开**，`parquet_io::import_parquet` 的词汇表前缀改从 collection 取、不再从声明取。映射的全部就是这一件事：还原进 ns 900 时，文件里的标签被 intern 进 ns 900 的编号——id 是局部的，标签才是身份。
- **`parquet_io::read_batches(bytes)`** 与 **`import_parquet_batch(collection, batch)`**：湖交出来的是字节，还原不该为了迁就一个吃 `&Path` 的签名而把字节绕一趟临时文件。`import_parquet` 现在是对批形态的读取循环，不是第二份实现。

## 4. 不变的东西

不要求另一个命名空间的调用方看到逐字节相同的键：`None` 就是声明的前缀，编码、索引、面、reduce 都不再过问 `ns_override`。没有第二条需要同步维护的写路径——同一条 `header()` 供 put、scan、index 与 fold 使用，这正是这个改动能只有一个字段大小的原因。

## 5. 已否决

- **每个目标 ns 一份声明类型**——同一批行，两套「它是什么」的真相；以后每加一个字段都要加两遍。
- **在存储层改写键里的 ns**——store 得解析每个键的头才知道自己在搬什么，这正是本 crate 存在的意义所在的那层耦合（引擎与 schema）。
- **变长的 ns 前缀（`Vec<u8>`）**——引擎已经承诺 ns 在头里是 2 字节；改成变长就等于让每个键的宽度取决于一个字符串。
- **只搬节点不搬边**（或反之）——见 §2：指向不存在的表的引用读起来是数据，不是错误。
- **在 `Collection` 上加 `restore` 动词**——还原是跨多张表的、以湖为形状的计划加一条拒绝规则，不是单表操作；它属于应用（k10r），空库策略也在那里。

## 6. 代价

还原从此是一张映射（`湖里的表 → ns`），全量还原是同一段代码配一张空映射。接受两条限制：映射还原出来的词汇表 id 与源库不同（标签是身份，id 是局部的）；表落在哪个 ns 由调用方决定——okm 不维护「这张表去了哪」的登记簿。
