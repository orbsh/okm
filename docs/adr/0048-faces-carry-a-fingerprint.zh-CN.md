# 0048 — 派生面带一个号：说得出自己是哪份声明写出来的

> **Languages:** [English](0048-faces-carry-a-fingerprint.md)（主）· [中文](0048-faces-carry-a-fingerprint.zh-CN.md)

**状态:** 已接受 (2026-10-31) —— 戳记与重建同一天落地。**日期:** 2026-10-31

## 背景

一张集合的派生面——`#[ok_index]` 的槽、动态段上的路径索引、图的五个面——都住在主表之外，各自在自己的 ns 里（`ns = table_ns + slot`）。在某个面下找到的一条条目只带着自己的键和值，没有别的东西：没有一样记录写着它是哪份声明产出的。

声明不动的时候这没问题。动的时候就有问题，而 payload 的 `LAYOUT_VERSION` 完全盖不住这件事：加一个索引不改任何 payload 字节，所以 layout 号不动、`ensure_layout` 通过、库照常打开，于是新面是空的，而被删掉的那个面还在答。没有任何一处处在能够发现这件事的位置上。

图是这种失败最难看的样子。ADR-0041 重排了图的面，于是它之前的库在「这个构建会读成别的东西」的槽号上压着条目——退休的谓词索引正好坐在 now out-edge 今天所在的位置。修法是 `Graph::reindex`，一把得有人记得去用的螺丝刀；整个模型层只有这一把，而且一个调用点都没有。

这个问题已经有两半被回答过，值得点名，因为它们都不是这一半。`#[ok_index(..., deprecated)]` 加 `Collection::prune_deprecated_slots` 处理「一个面被删了」：槽继续保留，条目被扫掉。ADR-0042 的规矩（「形状变了就换号」）处理 payload。两者都没覆盖的是：字节全对，而面的**集合**变了。

## 决定

**声明带一份自己诸面的指纹，库被打上这个号。**

1. **声明表。** `Document::INDEX_DECLS` 由 derive 从分配槽的那同一份清单里产出——名字、槽、索引字段、覆盖字段、函数路径、`deprecated`——所以它不可能与槽本身矛盾。没有索引的声明声明一张空表。

2. **号是算出来的，不是填出来的。** `Document::FACES` 从 `INDEX_DECLS` 在编译期算出：十六字节，两条独立的 64 位 FNV 车道，走一遍带长度前缀的规范编码，按声明顺序。手填的号是静默错误机器——整个失败模式就是「有人忘了升它」——而 payload 的 `version` 之所以能手填，只是因为忘了升它，下一次读会当场炸。这个号忘不掉，因为它不由任何人写。

3. **戳记住在表的 meta 行**（ADR-0043 的固定面 `0x0F`），名字是 `faces`，就在 `version` 旁边。那一行本来就是 name → bytes 的 map，存在的理由正是「新事实写在戳记旁边，不需要布局决策」，而指纹恰好是这种事实：不占槽、不占固定面。

4. **`ensure` 两个都写，只比对 `version`。** 新库的诸面平凡地就是即将写它的那份声明的诸面，所以两个名字一次落笔，不存在「有一个没有另一个」的库。比对故意不放在这条路上：`ensure_layout` 的承诺是「这个构建读得懂这些字节」，而这个机制之前的每一个库都会挂在一个它永远满足不了的检查上。说不清自己诸面的声明——手写 schema 背后的动态模式——传 `None`，它的库读回来是 `Unknown`，那就是事实。

5. **`Collection::faces_status()` 答三种，不是两种。** `Match`——这些面就是按这份声明建的。`Stale { stored, current }`——按另一份建的，它们为这个构建不使用的键布局作答。`Unknown { current }`——从来没记过号。过期与未知不是同一种失败，不能共用一个错误类型：过期是可修复的漂移，未知只是比机制更老。把任何一个折进 `LayoutMismatch`，都会把一次维护动作变成停机。

6. **导出两个都带。** `CollectionSchema` 新增 `indexes`（每个面同样六件事）与 `faces`（那个号），于是外部读取方——绑定、动态写者、运维脚本——不必自己再推一遍就能跟库比对。在 JSON 里两者都缺省为空；空读作**未描述**，绝不是「这张表没有索引」。

**指纹覆盖什么：** 只有声明的结构面。不含 reduce 累加器——它们是数据，重算它是另一套机制（一次全表 fold），那份成本不该被「加了个索引」带出来。不含图的面——它们的布局由格式固定，那里会漂的东西由 `reindex` 修。不含成员集——它在写侧被强制，不是任何面键的一部分。

## 后果

- **号不会腐坏。** 它是声明的函数，所以声明一变，它就在改槽的那同一个提交里跟着变。
- **打开一个库的行为不变。** `ensure_layout` 仍然只答 `version`；只有开口问的调用方才会得到关于面的裁决。现有库照常打开，只是答 `Unknown` 而不是假装。
- **盘上多了一个名字。** 更老的构建忽略不认识的 meta 名字，并且 `set_meta` 时把它们留着；这个构建打的库，老构建照样能读。
- **另一半是修复，而且是分块跑的。** `Collection::rebuild_faces(chunk)` 与 `Graph::reindex(chunk)` 先把声明点名的面扫空、再从主表的行重新派生，每 `chunk` 个操作提交一次——所以内存是一块，不是一张表，而 `usize::MAX` 恢复原来一次提交的形状。清扫必须在前、且不能省：条目的键编码的是它索引的值，所以一行换了手之后，旧条目答在一个今天没有行会产出的键上，重新派生只会写新键、永远点不到旧键。
- **中断不需要状态，因为戳记就是状态。** 两个动词都把 `faces` 写在最后，所以死在两次提交之间的那次运行留下的是一个仍然答 `Stale` 的库，下一次从头再来。代价是一个窗口：重建进行中的读者会看到只建了一半的面。这是运维契约（跑的时候别读），也正是为什么分块是一个显式动词、而不是 `put` 顺手干的事。
- **宿主声明的表一样有号。** `DynamicCollection` 没有 `const` 可算，于是 `faces::fingerprint_specs`
  是同一个编码器套在运行时形状上：这张表的访问方法就是它的声明，名字在导出 schema 认领该槽时借用，
  否则按种类合成（`plain` / `partial` / `func` / `path(<components> → <ty>)`）。镜像导出的动态表
  得出与编译期完全相同的号；声明了导出里没有的方法则合法地不一致，答案是 `Stale` 而不是愉快的
  `Unknown`——没有编译器盯着的那条路，正是此前唯一免于检测的那条。
- **结构结束的地方，由调用方开口。** `Func` / `Partial` 的可调用体是闭包盒，同一槽上换一个派生函数算出来一样。
  `AccessMethod.version` 就是答案：调用方给的数字随指纹入账，于是「我改了派生函数」成为一项声明而不是一段记忆
  —— 加一，表就答 `Stale`；重建之后条目属于新的函数。它从 `0` 开始（「无声明」），`Plain` / `Path` 也可以用：
  让条目过时的原因不止换闭包一种。访问方法仍然没有弃用态——方法要么被声明，要么从列表里消失。
- **有两个面不在这个动词里。** reduce 累加器是数据不是派生结构——重算它是整表 fold、另一套机制，这也是它们从来不在指纹里的原因。向量快照根本没得重算：它需要 embedding 模型，所以由它的主人 wipe 再重新 add（`okm_vector::VectorIndex::wipe`）。
- **动态模式继承这条规则，而不是被豁免。** 镜像导出声明的表得出与 Rust 构建完全相同的号（名字借自导出）；声明了导出里没有的方法的表则得出自己的号，并合法地不一致。没有谁被豁免，也没有谁因为少一个 `const` 而落在 `Unknown` 里。
