# ADR-0016：4 字节条目头与段号制 slot

日期：2026-09-18
状态：已接受（2026-09-18）。条目头是 `[ns 2B][slot]`，slot 的宽度随族而定（ADR-0030）：固定面占 1 字节、不带计数位；计数族保留 2 字节 slot——4 位段号加 12 位计数。下文的头宽决策对计数族成立；固定面表与号码归 ADR-0030。
取代：ADR-0005（1 字节 slot）、ADR-0011（edge slot 14/15）、ADR-0012（扁平固定角色 slot 表）中的 slot 分配部分。

## 背景

所有派生条目（索引、reduce）的 key 都以 `[ns 2B][slot]` 开头。1 字节 slot 是逐代生长出来的：固定角色占 0–15，声明的索引/reduce 从 16 续接，edge 钉死在 14/15（ADR-0011），条目**种类**之间没有任何结构性隔离——段归属只是纪律约定，slot 字节本身不携带"这是什么种类的条目"的信息。

容量配比也曾与消费者错位：u8 slot 给每个角色同样的 256 预算，而真实消耗极不对称（固定角色屈指可数，声明索引随声明增长）。

## 决策

计数族的条目头是 4 字节——**ns u16 + slot u16，均大端**——slot 内部结构化拆分：

```text
slot u16 = [段号 4 bit][计数 12 bit]      （计数族）

0x2nnn  词汇表：label → id   计数 = 词表自己的编号
0x3nnn  词汇表：id → label   同一个计数，另一个族
0x4nnn  声明索引             计数 = 声明序
0x5nnn  reduce               计数 = 声明序，独立配额
0x6nnn  前导面               计数 = 声明序
```

（上表是当前带子的编号；ADR-0030 保留了两字节计数族，ADR-0033 加宽了固定面带子。
本 ADR 记录的裁决就是段分派——`slot >> 12`——这一点没有变。）

完整分配与固定面表归 ADR-0030。固定面不是带计数位的 slot：它占 1 字节，`0x00–0x1F`，自带号码、没有段号——主表 `0x00`、动态段 `0x01`、两本词汇表 `0x02–0x05`、图的面 `0x06–0x0D`、句柄登记册 `0x0E`/`0x0F`、Extension `0x1E`、表元数据 `0x1F`。

- **段提取是结构操作**：`slot >> 12`（计数族）。数值区间约定变成类型化分派——把某段的 slot 用到另一种条目上是布局错误，不是纪律失误。
- **计数宽度**：每个计数族的计数位容纳 4096 个条目。一个集合承载 4095 条声明索引与 4095 条 reduce，各自独立配额。
- **16 个段号作为枚举足够**：段是条目**种类**的枚举，不是空间分配。耗尽 16 个种类意味着语义革命，本来就该走版本迁移。
- 实现中整个头是一个 u32：`((ns as u32) << 16) | slot`。扫描前缀构造与段分派都是移位，无查表。
- 计数族条目比固定面多付一个 key 字节。相对多字节身份载荷不可见；主键（固定面 0x00，1 字节）所在文档自身 key 形状不变。

## 后果

- 计数族条目装 2 字节 slot，固定面装 1 字节；hex 锁测试同时钉住两种宽度。
- reduce 与索引的计数器是各自独立的配额。
- `SlotMap`（schema 导出）装 u16 号码：各个固定面，加上 `declared_index_base` 与 `declared_reduce_base`。
- `KvIndex::SLOT` 是 `u16`（`type Slot = u16`）。
