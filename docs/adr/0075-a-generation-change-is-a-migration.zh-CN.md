# 0075 — 代际变化是一次迁移，一次一张表

状态：2026-11-20 裁决，尚未落地。

## 背景

ADR-0074 §2 与 §4 让 store 自己描述它的表：meta 行和每个 segment 头都把声明按字节带上，attach 再把这份副本与本次构建从类型编译出来的那份对比。在这之前，声明只存在于二进制里——store 没法跟一次构建意见相左，因为它自己不持有意见。现在它可以了，而它得到的回答只有一个 `LayoutMismatch`：一扇门，门后什么都没有。上一代的 store 就是本次构建用不了的 store，今天能写出来的唯一迁移是"全量导出、全量清空、全量导入"。

这个回答错两次。它让没变过的表为变过的那张付账，而且在任何人说清那些字节是什么之前就把它们丢掉。

决定形态的是四条事实。

- **key 里带的是 ns，不是代际。** 一个 key 是 `[partition 前缀][ns: 2 字节][编码后的主键]`；`layout_version` 只存在 segment 头和 meta 行里，从不进 key。所以两代不能共用一个键空间：旧行和新行是同一个 key，回填是落在唯一那份副本上面。
- **代际本来就是按表并存的。** 日志是一张表一个目录，一个 window 装一个代际、在下一个代际开始处结束（`window.rs`：「日志目录从不改变，所以升级后这就是常态」），`load_declaration` 回答最新那一代。日志做不到的是不用该 segment 自己带的声明去读它——而它能在换代之后继续可用，原因正是这一条。
- **日志是包装器，不是 store。** `ChangelogStore<S>` 是 `VirtualStorage`，staging 只在它的 `commit_batch` 里。建在裸引擎上的 `Collection` 写下去什么都不记。ADR-0062 的 restore 已经依赖"这件事由装配点决定"这个缝，用的是 `ns_override`；本决定用同一个缝，理由相同。
- **ns 是编译期的**（ADR-0002），`ns_override` 是唯一的旁路。store 里没有任何地方记着某张表当前在哪个 ns 上——"把这张表指到另一个 ns"是调用方的事实，不是存储的事实。

## 决定

1. **迁移的单位是表。** 一份声明描述一张表，一次对比失败点名一张表，其余的表在它移动期间照常服务。全 store 迁移就是按表迁移做 N 次，其中 N−1 次是不必要的。

2. **attach 有两个回答，第二个是一个状态。** 同代际：正常打开。不同代际：这张表被**封存**——类型化句柄读写一律拒绝，错误里带表名、两侧代际和那个负责迁移的动词。本次构建能不能把某个已存的代际移过去，属于迁移器的问题；attach 不去猜。

3. **封存针对类型化句柄，不针对字节。** segment 用它自己带的声明读（`declaration_of`、`segment_labels`、`load_declaration`），永远不用本次构建的 `R`，所以导出这条腿在一个本次构建本来碰不了的代际上照样能跑。这正是迁移唯一需要的那条读路径，而它已经存在。

4. **迁移是快照、换血、校验，而换血期间没有读者。**

       快照   按表自己的声明把封存的表导出到 lake，然后校验它
              （行数、存储声明的指纹）
       换血   清空该 ns，通过建在裸引擎上的 collection 重写每一个文档；
              这段时间读也拒绝
       校验   新代际上核对条数与逐 key 读取，然后解封、
              真空掉旧代际的 segment

   快照就是换血期间的读来源。清空那一趟是对 `[partition][ns]` 的无条件前缀扫描：如果只是 payload
   布局变了，回填本来会覆盖每一个 key；但新声明丢掉的字段，它留下的索引条目没有任何东西去覆盖，
   所以这一趟不取决于"变了什么"。

5. **回填不记日志。** 日志记录的是变化，重写每一行不是变化。记日志的回填会让 lake 去回放一次
   全表写，也让同一次换血对同一张表有两个真相来源。旧代际装了什么，由快照记录一次，时间点是它
   停止可写的那一刻。

6. **驱动是 lake 的一条子命令，不是新 crate。** 腿都在——`baseline`、`read`、`restore`、`publish`、
   `delta`、`vacuum`——缺的是判定（比代际、指纹、schema 字节）、换血和校验。独立的 `okm-migrate`
   crate 会把 lake 的桥接再抄一遍，在同一件事上做第二份实现。

## 由此得出

- `LayoutMismatch` 不再是终点错误，而是一个调用方可以据此行动的值：它点名的表就是要迁移的表，别处都不停。
- lake 多一个动词；`PLAN.md` 记成本 ADR 撑着的待办条目。
- 重写过的表在真空之前保留旧 segment，所以校验失败只需要重跑，而不是数据没了。
- `ns_override` 保持 ADR-0062 给它的位置——restore 的映射——不会变成通用的"我在哪一代"开关。

## 否决

- **全 store 迁移。** 它就是按表迁移重复 N 次，而且让没变的表付账。
- **跨第二个 ns 的真蓝绿**——把新代际建在正在服务的表旁边再 flip。它能让换血期间读不中断，但需要一层"表 → 当前 ns"的间接：每次打开都要读一次目录行，而这正是 ADR-0074 §3 刚从写路径上拿掉的那次查表。等"迁移必须在有读者服务的情况下进行"成为部署事实时再开，那是部署问题，不是设计问题。
- **给旧代际一个只读句柄。** 用本次构建的 `R` 去解码上一版布局，就是 attach 存在的目的要拒掉的那种误读；一个被允许这么做的读者，就是一个"靠碰巧决定"的读者。
- **没有快照的原地改键。** 键空间里一行只有一份副本，改到一半失败的键重写会留下两种布局都不成立的状态。
- **在 store 旁边放一个迁移标记。** segment 头里的代际已经说明是哪个声明写的字节；文件外的第二个标记就是对同一张表的第二个真相。
- **在 attach 里做迁移。** 一次会重写表的 open，就是一次会因为调用方没问过的原因失败的 open。
