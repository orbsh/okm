# 0075 — 代际变化是一次迁移，一次一张表

状态：2026-11-21 裁决，尚未落地。

## 背景

ADR-0074 §2 与 §4 让 store 自己描述它的表：meta 行和每个 segment 头都把声明按字节带上，attach 再把这份副本与本次构建从类型编译出来的那份对比。在这之前，声明只存在于二进制里——store 没法跟一次构建意见相左，因为它自己不持有意见。现在它可以了，而它得到的回答只有一个 `LayoutMismatch`：一扇门，门后什么都没有。上一代的 store 就是本次构建用不了的 store，今天能写出来的唯一迁移是"全量导出、全量清空、全量导入"。

这个回答错两次。它让没变过的表为变过的那张付账，而且在任何人说清那些字节是什么之前就把它们丢掉。

决定形态的是四条事实。

- **key 里带的是 ns，不是代际。** 一个 key 是 `[partition 前缀][ns: 2 字节][编码后的主键]`；`layout_version` 只存在 segment 头和 meta 行里，从不进 key。所以两代不能共用一个键空间：旧行和新行是同一个 key，回填是落在唯一那份副本上面。
- **代际本来就是按表并存的。** 日志是一张表一个目录，一个 window 装一个代际、在下一个代际开始处结束（`window.rs`：「日志目录从不改变，所以升级后这就是常态」），`load_declaration` 回答最新那一代。日志做不到的是不用该 segment 自己带的声明去读它——而它能在换代之后继续可用，原因正是这一条。
- **日志是包装器，不是 store。** `ChangelogStore<S>` 是 `VirtualStorage`，staging 只在它的 `commit_batch` 里。建在裸引擎上的 `Collection` 写下去什么都不记。ADR-0062 的 restore 已经依赖"这件事由装配点决定"这个缝，用的是 `ns_override`；本决定用同一个缝，理由相同。
- **ns 是编译期的**（ADR-0002），`ns_override` 是唯一的旁路。store 里没有任何地方记着某张表当前在哪个 ns 上——"把这张表指到另一个 ns"是调用方的事实，不是存储的事实。

## 决定

1. **迁移的单位是表。** 一次声明描述一张表，一次失败的比较点名一张表，其余的表照常服务。整库迁移就是按表迁移做 N 次，其中 N−1 次是白做的。

2. **代际是地址里的一位。** `#[ok_ns]` 仍是表的身份，永不移动；`LAYOUT_VERSION` 的奇偶放在 ns 首字节的最高位——`ns < 0x8000`，在声明处断言——于是每把数据 key、每条索引条目都带着它，而版本是编译期的，header 因此仍是常量：`[partition][ns_hi | parity << 7][ns_lo]`。相邻两代因此落在同一张表的两段不相交区间里，一个 store 可以同时持有。代价只有 ns 空间（每 store 32768 张表），别无其他：偏移、槽位、key 宽度一字不动——这正是它是一位而不是一字节的全部理由。长出 32768 张表的 store，是该拆应用了，不是该把地址加宽。

3. **每一代记录自己，版本大的那一份是当前代。** 表的记录行按代各一份，落在 `[partition][ns|parity][0x1F]`，带着这一代的 schema、版本与 capture 标记。attach 两个奇偶各探一次，取版本大的那个：只有一行就是安静的表，两行就是"已经翻过、旧代等 vacuum"。没有指针行、没有封存、没有阶段字节——新那份记录的版本**就是**指针，翻转是一次 put，崩溃留下的状态下一次 attach 不必猜：翻转之前新区间没有记录（下一次尝试整段清空重来），翻转之后取大值即新代、vacuum 接着做。记录按代存放，旧布局因此能从 store 自身解出——这才是一个从未持有旧声明的二进制也能续跑迁移的原因。

4. **一个句柄只说一种布局，追赶靠日志。** attach 拒绝"store 的当前代不是本声明的代"，于是每个打开的句柄都只解一种布局：窗口期内旧代服务**所有**读——不做第二次探针、不要墓碑、读路径里没有双解码器。迁移者按新声明把旧区间拷进新区间，记下开始拷的位置，然后从那个位置起把旧代的日志按同一份声明重放，直到追平一个安静窗口的头部。日志本来就记着这期间的一切变化——段带着写它的那份声明——所以没有任何东西被写两遍，也没有逐写的镜像可做错。

5. **翻转是一次静默，不是停机。** 停止接写入、重放最后一片、写下新记录、在新代上恢复：一个微秒级的窗口，与表的大小无关。耗时的是拷贝，而拷贝从不占住写者。

6. **拷贝不是变化，重放的尾巴是。** 拷过去的行是新代的基线——湖负责钉住或导出它们，日志不是"搬了什么"的账本。重放的变化是变化，它们以新代的 header 进日志。这也是旧代日志必须活过翻转的原因：快照到切换之间发生的事，只有它记着。

7. **驱动是湖的子命令，不是一个 crate。** 腿都齐了——`read`、`restore`、`publish`、`delta`、`baseline`、`vacuum`，以及重放目标——缺的是判定（比代际、比指纹、比 schema 字节）、拷贝与翻转。另起一个 `okm-migrate` crate，只会把湖的桥复制到第二个地方。

## 由此得出

- `#[ok_ns]` 受限于 `0x8000` 以下，在声明处断言——首字节的最高位属于代际。
- `TablePlan::compile` 从 `schema.layout_version` 推出奇偶位，于是从存储字节编译出来的 plan 与声明给出的 header 一致——每代一个 plan，精确匹配，任何地方都不需要掩码比较。
- `LayoutMismatch` 不再是一个终止错误，而是调用方可以据以行动的值：它点名的表就是要迁移的表，别的不停。进程若发现 store 的代际**更新**，那是自己过期了，说出来，而不是拿着读不懂的字节继续跑。
- 湖多一个动词；`PLAN.md` 把这条记为本 ADR 支持的开放项。
- 迁移过的表在 vacuum 之前保留旧区间与旧记录，所以校验失败只需重跑，不丢数据。
- `ns_override` 仍保持 ADR-0062 给它的含义——restore 的映射——不会变成通用的"我在哪一代"开关：代际在 key 里，不在句柄的选项里。

## 否决

- **整库迁移。** 它是按表迁移重复 N 次，还让没变的表陪跑。
- **可移动的 ns**——在 `ns + 1` 下建新代、拷贝、删旧的。它要求每次 open 查一次"名字 → ns"，而 derive 表达不了：`#[ok_ns]` 是常量，plan 静态量、湖表名、日志认表全都按它算。一位买到同样的共存，代价落在地址上而不是一条目录行。
- **header 里放一个版本字节。** 同一个想法，尺寸错了：它会把每个槽位与 key 字段的偏移都推后，并让每把 key、每条索引条目多付一个字节——为一个一位就够表达的区分。
- **两代合并读。** 读新区间、没有再回落到旧区间，要求读路径里有一个双解码器和一套墓碑，而且迁移之后也留在那里——影子方案的成本由每个读者永远承担，而不是由一次重放承担。
- **用本构建的 `R` 去解旧布局。** 那正是 attach 要拒绝的误解。迁移者用的是**存储的**声明，这是另一回事：它读到的声明指明了布局，它编译的 plan 来自那些字节。
- **没有快照的原地 key 改造。** keyspace 里只有一行的一份，改 key 改到一半，两种布局都没了。
- **store 旁边立一个迁移标记。** 代际在 key 里、记录里还写着布局；文件外的第二个标志是关于同一张表的第二个真相。
- **在 attach 里做迁移。** 一次会重写表的 open，就是一次可能因为调用方没问过的原因而失败的 open。
