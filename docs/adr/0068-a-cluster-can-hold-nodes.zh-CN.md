# 0068 — 簇可以装节点

状态：2026-11-17 裁决，已落地。收窄 ADR-0066 §2（那一节把参与者留在存储之外、拒绝节点面），并在 ADR-0066 打开的那条带上加两张面。

## 背景

ADR-0066 定下：簇的成员是边，簇里的**节点**是成员边的端点，在读取侧投影。这个决定有两个后果在咬人：

- **一个没有边的实体根本进不了任何组。** 模型的完备性规则是节点只作为端点存在（`Error::BareNode`），于是一条权限边界没法点名一个还没有任何断言的实体，一个空社区也没法说明它本该收谁。
- **"这个实体在哪些组里"要按关联边逐条扫**——`出度 + 入度 + 1` 次前缀扫，簇流自己的代价注释里就是这么写的。那是对一张按边做键的面正确的价钱，对一个高连接节点是错误的形状。

一组实体也不是一组边更差的写法。社区发现产出的是顶点划分；把它编码成"这次运行归到一起的那些边"，要给每条跨组的边额外定一条约定（归左、归右、两边都算），而且会静默丢掉所有孤立顶点。两者是同一张图上不同的关系，存储应当能装下生产者手上那一种。

## 裁决

**1. 两张成员面，一个簇身份，一本 kind 词表。**

```text
0x0D  边成员       [ns][kind][簇号][src_h][pred][dst_h]  → 空（权威）
0x12  节点成员     [ns][kind][簇号][句柄]                 → 空（权威）
0x0F  边 → 簇      [ns][src_h][pred][dst_h][kind][簇号]  → 空（派生自 0x0D）
0x13  节点 → 簇    [ns][句柄][kind][簇号]                 → 空（派生自 0x12）
```

面号归布局模块所有，那里是全引擎唯一写下数字的地方。

**没有边 → 点簇的面。** 一条边的端点恰好两个，所以"这条边沾到哪些点簇"是 `0x13` 的两次前缀扫——常数。节点的度无界，这才是边侧需要镜像面而点侧不需要的原因。不对称来自基数，不是偏好。

**2. 成员类型由面承载——不写进 `kind`，也不加标记位。** `kind` 仍是调用方的词汇，okm 不对它赋予任何含义。ADR-0066 写过存储永远学不会应用的词汇表；同一条规则也禁止 okm 把自己的词（成员类型）强加进应用的词汇里。而行头里加一个标记字节要付一次值布局的戳（ADR-0042），而且仍然答不了一个空簇——没有行可读。

于是一个簇可以装边成员、节点成员，或两者都装，而**"谁在这个簇里"是声明的节点成员与成员边端点的并集**。一个作用域有多大，是它那些行的事实，行就是答案。API 只声明其中一种、从不一次声明两种：断言组与实体组是两个集合，两样都要的调用方自己声明两份、自己把它们关联起来。

**3. 节点成员是声明的真值，不是成员边的投影。** 这是收窄 ADR-0066 §2 的那一半。投影装不下一个没有边的实体，也无法在一条边被删时保住一个实体仍然属于的组；成员行两件都能做，而且它正是 ADR-0066 §1 在"把组实体化成节点"之外选的那条"一行一个成员"。

**4. 一条规则变了，它只说一次：** 节点作为某条边的端点存在，**或者**作为某个点簇的成员存在。`Error::BareNode` 在边的路径上保持原义——仍然没有"创建一个裸节点"的动词——所以 `delete_node` 不能再用"没有关联边就等于不在图里"作为判断，它要扫这个节点的 `0x13` 段。

**5. 面与角色和边侧完全对齐。** `0x12` 归 Truth，`0x13` 归 Derived 且只用 `0x12` 就能重建；`rebuild_derived` 在已有的 `0x0F` 之外多一个阶段。删除遵循同一套：删簇带走两张成员面和两张镜像；删**节点**带走它的 `0x12` 行（经一次 `0x13` 扫描找到）；删**边**不动任何点簇——一个实体不会因为一条关于它的断言消失就离开组。

**6. 计数是重写的，不是自增的。** `edge_count` 是边成员数，`node_count` 是节点成员数。两者都在每次动到那张面的写入里按面重算——现有那个计数本来就是这么来的，也是写路径不需要跨行读改写的原因。

**7. 一份声明、没有特例，且构造函数说清它带来哪种成员。** 两种拼写是 `EdgeSet` 与 `NodeSet`——schema 那一层的 `NodeKinds` trait 保留自己的名字，因为「一组成员表」与「一组实体」不是一件事。 `Cluster::nodes(kind, 载荷, iter)` 声明一个只装**实体**的簇，不收边——同一碎片写的边溜不进来；`Cluster::edges(kind, 载荷)` 声明一个装本碎片断言的簇。没有一份声明能同时带来两种成员，也没有 `with_nodes`：实体组与断言组是两个集合，两样都要的调用方写两份声明，计划按 `(kind, id)` 记账，所以同一个 `id` 上的两份声明写下的仍是一行。动词写明成员类型，而不是让边侧占走那个没标记的名字：`edge_members` / `node_members`、`edge_member_of` / `node_member_of`、`edge_count` / `node_count`、`remove_edges` / `remove_nodes`，`node_sets_of(node)` 是一次 `0x13` 扫描。叫 `members` 的动词摆在 `node_members` 旁边，等于把节点一侧写成例外，而它不是例外：两张面地位相等，唯一的不对称是基数。声明的撤回是 `remove_nodes(cluster, nodes)`：它只对声明的半边说话——成员边仍然点名的实体留在并集里，实体本身一个字节都不动。

## 命名

散文里叫**边簇**与**点簇**；代码一个新词都不需要，因为现有那条轴本来就能推广：簇在前的那张面叫 `*_MEMBER_SLOT`，X 在前的镜像叫 `*_CLUSTER_SLOT`，改动只有 `EDGE_` → `NODE_`。

`hyper-edge` / `hyper-node` 被否。文献里的超边是一组**顶点**，所以这一对在这里是反的——点集才是超边，边集只有在线图视角下才是，而这正是 ADR-0066 已经点明的那层错位。而 `hypernode` 在关联（星形）展开里指代表一条超边的那个实体化结点，也就是 ADR-0066 §1 明确拒掉的形态：用这个词，等于把被否的设计请回词汇表。

## 代价，写在付出的地方

- 节点成员行二十一字节，边成员行三十一；镜像面同样二十一与三十一。
- 声明的点组写的行数就等于它声明的节点数——没有按边的乘数。它的写要付一次自己 `0x12` 段的扫描来重写 `nodes`，与边面为 `edge_count` 付的是同一形状。
- 普通的节点与边的写仍然不碰任何簇面：计划只从碎片的声明里建，所以一个不声明簇的碎片计划为空、什么也不读。
- 级联：删一个节点多一次 `0x13` 前缀扫（精确，而且比边路径需要的整面后缀扫便宜），加上每个受影响的簇一次计数重读。
- 边簇的参与者仍然是一次读取侧的投影。这一点没变，也仍然是便宜的答案：组里的边是连续的，去重是一次有序插入。

## 被否

- **派生的节点面——ADR-0066 §2 拒掉的那个镜像。** 它装不下没有边的实体；而且在收回时，它分不清"这个端点的最后一条成员边走了"与"这个实体本来就属于这里"，除非存一份按 `(簇, 节点)` 的计数，也就是一行被多条边写——正是写契约拒绝的跨行读改写（ADR-0066 自己对"把集合存成一个值"的否决，以及 PLAN 里的位图条目）。绕着它走、每次成员变化都重推整张面，则把每次删边变成对那个簇的一次全扫。
- **把成员类型做成 `kind` 的一个值。** `kind` 是调用方的词汇；okm 强加一个值，会让一个库的名词取决于另一个库的结构，也会撞上一个应用想给自己的点组留号的情况。
- **在簇行头部加标记字节。** 它要改 `0x0C` 的值布局（ADR-0042 的戳），去回答一个面已经回答了的问题——而且对空簇依然答不了，而模型明确允许空簇、并且把它当信息。
- **边 → 点簇的面。** 基数恒为二：推导就是两次前缀扫，而一张面会是每个 `(边, 簇)` 一行、去维护一个常数成本的读。
- **只留节点成员、砍掉边成员。** 会丢掉集合在断言层面的身份：同一批顶点上的两个边集怎么区分、一条边被两个组共用、一条边自己的角色。ADR-0066 §1 为这些定过价，它们今天仍然成立。

## 后果

- "这个实体在哪些组里"是 `0x13` 的一次扫描，再并入关联边那条路径——实体侧的召回不再随度数线性。
- 一次社区发现可以直接写一个顶点划分，不需要为跨组的边定约定。
- 两条关系共用一种行型：断言组的参与者是推导出来的，实体组的是声明出来的。API 分开声明（`Cluster::edges` / `Cluster::nodes`），没有任何动词答并集；一行上两张面都被填满，只发生在调用方刻意在同一个 id 上声明两份时。两张面之间没有任何不变量约束，因为它们是不同的事实，不是同一份事实的两个副本。
- 节点存在的链路不再唯一：一个端点，或者一个声明的成员。每一条曾假设前者的路径，都要说清它指的是哪一种。
