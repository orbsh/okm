# 0070 — 替换是一批，切口由调用方说出

状态：2026-11-17 裁决，两种形态均已落地（`okm-core`、`okm-dynamic`）。

## 背景

三种形态是同一个操作：合并两个实体、拆分一个实体、以及在一组不动的实体之间换掉那片子图。三者是同一个主张——「这个形状变成那个形状」——而且都能表达成删除加声明。

有两件事让它在现有动词下**根本表达不出来**：

- **两个动词互不接受。** `incorporate` 拒收带删除的碎片（`IncorporateWithDeletes`），`retract` 拒收带声明的碎片（`RetractWithWrites`）。把它们拼起来就是两次提交，而两次提交之间旧形状已经没了、新形状还没到：实体的边指向一个不存在的端点。这正是替换要消灭的那种状态，两次提交无论怎么排列都躲不掉。
- **搬走的断言带不走 payload。** 边的 head 就是身份（ADR-0067），换一端就是另一行。用 `delete_edge` 加一个声明去重写，落下的会是该 payload 类型的**默认值**——声明只给 head，创建路径喂给冲突钩子的是 `(default, default)`，它看不到被替换的那一行。

第一件是事务问题，引擎已经给了答案：一次 `commit_batch` 在 fjall 上就是一个原子写批。第二件是批内的读，okm 做得到、调用方做不到。

## 决定

1. **`Graph::replace(fragment)`** 收一个既删又声明的碎片，作为一次状态变更落地。两半**一起规划**：删除半边的移除项作为写入半边簇计划的种子，所以每个被碰到的簇只读一次、只算一次、只写一次。把两半拆成同一批上的两遍，第二遍会读到批前的行、重写一个忽略第一半的计数——那是静默写坏，不是性能注脚。
2. **`Fragment::repoint(from, to)`** 把一条断言连同 payload 搬到新 head。目标为空：payload 原样落地。目标已有行：`on_edge_conflict(目标已存, 搬来的)` 决定，搬来的那条算声明方。开放属性（按边键的动态段）**不归 okm**，留在调用方。
3. **`Graph::cut(NodeSet)`** 是拿调用方**已经持有的选择**去问切口——它不是「读子图」，选择本身就是子图——答的是替换所需的东西：每条跨过边界的边给出一个半边（成员端，即要重接的一端，加上远端），以及随选择一起死的内部边。代价是选择范围内的度数，内部边按 head 去重，因为两端都会到达它。
4. **完备性强制。** 让一个实体退休的替换，必须把它的每条关联边说清楚——repoint 或删除——否则整批拒绝（`ReplaceIncomplete`）。级联是删除的正确答案（「断言反正都没了」），是替换的错误答案（「没人决定过的连接」）。
5. **旧动词各自一个含义**：`incorporate` 把 repoint 计为删除并拒绝，`retract` 把它计为写并拒绝。只有 `replace` 收。

## 由此得出

- 处在**链条末端**的选择边界上只有一条半边、**游离**的选择一条也没有。两种都普通：前者有一端要接，后者没有要接的地方。合并的一对成员之间的边会变成自环，而它是退休实体的关联边，所以完备性规则已经强制调用方删掉它。
- 选择有**两个来源**：一个簇（别人已经决定好的划分），或者 `subgraph(seeds, hops, predicates)`——后者从一组种子出发，走完直接答一个 `Cut`（`cut` 就是零环的同一次走，两者不可能给出不同答案）。`hops` 数的是**在选择之内**的环数，所以边界是离开这些环的边：多走一环并把看到的节点加进来，边界永远是空的，因为 k 跳邻域自身的边界按构造就是空的。
- 算出来的选择不等于存下来的选择：把它写成节点组是显式的一步（`materialize(selection, kind, payload)`）。两者分开，读才不会背着调用方写行。
- **只换实体之间的边、实体不动**，是同一个动词去掉节点删除的用法，完备性规则因此不会触发；边的删除从不碰端点，也是同一个道理。
- okm 唯一不替调用方决定的，是拆分时那条唯一的边界半边归哪一半。那是判断，存储里没有依据。
- **这里没有任何派生。** 替换不跑 reduce、不自造计数器，碎片声明什么就落什么。
- **不做 id→id 别名面**，虽然考虑过：重定向断言「这个编号现在就是那个实体」，而经过一次拆分、一次部分合并回、一次后来的吸收之后，这句话是假的。静默改写历史比缺一行更糟——存储只存当前为真的事，形状为什么变了的记录是应用的数据。
