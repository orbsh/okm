# ADR-0017：图 Edge——第三种关系载体

日期：2026-09-19
状态：已接受（2026-09-20）；**身份子句已被 ADR-0067 取代**（2026-11-14）——边没有号，身份就是元组 `(src, predicate, dst)`，下文按这一形态陈述。声明就是**图的声明**（`GraphEncode`）：一个 ns、边自己的载荷（复用文档编解码）、它显式声明的属性面，外加一个编译期节点类型枚举。`#[ok_nodes]` 按类型列出成员**表**（`#[ok_nodes(EntityRow, MemberRow)]`），derive 写出成员集枚举及其 `NodeSet` impl，每个 ns 取自那张表自己的 `#[ok_ns]`。谓词词汇表在 0x04/0x05，图的面在 0x06–0x09；`Graph<S, E>` 是不声明任何东西的运行期句柄，`Graph::new(store)` 绑定引擎实例，删除时读 0x06 那一行、精确删掉它声明面的条目。okm-dynamic 的句柄收 ns + schema 一对（`CollectionSchema::ns_prefix`、`members`）。
关联：ADR-0015（关系分类学）、ADR-0016（4 字节头、段号制 slot）、ADR-0002（命名空间词汇表）

## 背景

关系分类学（ADR-0015 §3）有两种载体：`Refs<D, K>` 承载一对多（字段位、单向、固定父类型的孩子），`Junction` 承载多对多（独立条目、双物化、双端编译期定类型）。两者都把端点**编译期绑定到已声明的文档类型**——derive 解析 `<D as Document>::Key` 与 `NS_PREFIX`。

图应用打破这个绑定。知识图谱或 LLM 写入的属性图具有：

- **异构端点**——一个图连接多种类型的节点（Person、Org、Document……）；为每种端点类型组合声明一种 Edge 是组合爆炸。PGQ 把这条界线画在另一头，本 ADR 跟随它：属性图**声明**它的顶点表与每条边表的 SOURCE/DESTINATION 引用——一条边表可以引用多张顶点表，一张表也可以用不同别名同时当顶点和边——而每条边的节点**类型**是一份声明，不是每对一份。PGQ 禁止的（本 ADR 也禁止的）是**未声明的参与**。
- **运行期涌现的谓词**——边的谓词（"has"、"owns"），即它的类型，是数据：它走边集合自己的词汇表分配。节点**集合**恰好是反面：ns 词汇表是编译期闭合的（ADR-0002，"词汇表是代码"），所以知识图谱的节点是**已声明**集合的行（facts、entities、users 这样的集合），绝不是随手新建的集合；一个集合内部的节点"类型"是一个载荷字段。全动态形态下节点 kind 同理。
- **边的身份与属性**——平行边存在（同两节点间的两个 "has" 是两个事实），边携带动态属性。两种载体都不支持：Junction 的身份就是端点对，且两者都没有 per-edge 载荷。
- **独立存在**——边在查询范围内先于或后于端点文档存在；边集是一等集合，不是派生视图。

`Refs` 表达不了（孩子类型固定、字段位、单向、无属性）。`Junction` 也不行（端点类型固定、无边身份、无属性）。图 Edge 是**第三种关系载体**。

## 决策

### 1. 边**集**是一等集合，每图一个 ns

一个图的边住在自己的 Edge collection——一个图的边集一个 ns，走正常 ns 词汇表分配（ADR-0002，"词汇表是代码"），与任何文档集合对称。无新命名空间机制：不是每种谓词一个 ns（动态形态下谓词是运行期数据），不是全局边池（图在 ns 层隔离），不是寄生（边独立于端点文档存在）。

集合是一等的；里面的一条边是一行，身份只有它的元组（ADR-0067），所以没有需要维护的边登记表、没有要发的号、也没有还原时要保住的东西。

同一个 ns 承载边集的所有条目种类，按 ADR-0030 的固定面 slot 分派。

**成员节点集是声明，不是注册表。** 一个图声明它可以有哪些集合充当节点——这是编译期事实，写在代码里，与它所依赖的 ns 词汇表放在一起（`Node` 枚举；§4）。它不占 slot：这个集合不带来任何运行期信息（每个候选集合本来就是一个编译期 ns），而一条元数据条目只会附赠"谁写、什么时候写、冲突算谁的"。运行期新建节点集合随之被否决：知识图谱的形状是**已声明**的集合、其行带类型字段——一个 ns 承载多种运行期类型——这比"每种涌现类型一个 ns"严格更便宜，也是唯一能保持 ns 词汇表闭合的读法（PGQ 自己的规矩：表要声明，不能凭空变）。

### 2. 端点引用：ns 在引用里，宽度来自声明

端点**不是编译期定类型**。引用是 `[ns 2B BE][pkey]`——任意成员集合的文档，**前面没有长度**。ns 充当类型标记：解码引用按 ns 路由到归属 collection，节点类型不受限。

pkey 宽度**不是 wire 数据**，它来自图的声明：`#[ok_nodes(..)]` 是一组编译期已知的闭合成员表，`KeyEncode` 每份声明只产出一个定宽字节数，所以图一开始就知道每个成员的 key 宽度。于是引用不为宽度付任何字节，`[src][pred][dst]` 只靠宽度解析、顺序即值序、每跳零开销（ADR-0067）。ns 知识仍然住在引用自身：不存在跨集合的宽度注册表。

于是声明的成员集**同时**是宽度来源与校验：写入时应用（端点 ns 不是成员即 `Error::ForeignEndpoint`；pkey 宽度不符即 `Error::Corrupt`），解码时也应用（ns → 变体；越界即错误，绝不静默）。推论是一条约束：想出现在图里的表必须有定宽键。变长字段照样可以在集合内部被索引；它们被拒绝作为成员身份。变长键确实要参与时，诚实的选项是补到某个声明宽度，或接受哈希身份连同它的碰撞校验——不是往每条键里塞一个长度。

### 3. Slot 分配（固定面与计数族，在 Edge ns 内）

```text
0x00  主表          （边不写这一行——0x06 就是边本身）
0x01  动态段        [src][pred][dst]（边的开放属性）
0x02/0x03  字段名词汇表  （载荷自己的名字 ↔ 号）
0x04/0x05  谓词词汇表    （谓词名 ↔ predicate_id；本图的谓词）
0x06  出边／边本身  [src NodeRef][pred][dst NodeRef]  → 边的载荷
0x07  入边          [dst NodeRef][pred][src NodeRef]  → 空
0x08  谓词正向      [pred][src NodeRef][dst NodeRef]  → 空
0x09  谓词反向      [pred][dst NodeRef][src NodeRef]  → 空
```
（每张面同时携带两端**与谓词**（ADR-0041、ADR-0067）：`(src, predicate, dst)` 在 0x06 上可寻址，`(predicate, src, dst)` 在 0x08 上。这些键里的引用是 `[ns 2B][pkey]`、不带长度——宽度是声明的（§2）。图的面是固定面号——各一字节，ADR-0030；下文的声明属性面属于计数族 0x1。表里按**角色**排：两本词汇在前，读它们编号的面在后——词汇表排在它所服务的面之前；**编号**才是机制。）

**谓词有自己的一本词汇表。** `[ns][0x04][predicate_id] → 谓词名`、`[ns][0x05][谓词名] → predicate_id`——与 0x02/0x03 同一双向形状，另一套词汇。于是"列出这张图有哪些谓词"就是扫一次 0x04 前缀：确切名单，永不靠走索引面反推。与载荷字段名共用一本的话，名字彼此分不开，"一个图里有哪些谓词"只能靠走遍历面反推——而列举不该是推断。在同一本里按 id 号段切分同样不行：号段是约定，第一次越界分配就静默失效；再加一对固定面是结构。代价：用掉一对固定面（0x04/0x05，ADR-0030），边集合从此有两套词汇。字段名词汇表（0x02/0x03）对载荷自己的名字保留文档侧含义。

**这一对是图自己的谓词词汇表。** 0x04/0x05 这对号也不是图专有的：它是集合在字段名**之外**自己的 token 词汇——这里是一张图的**谓词**；**节点集合**声明了 kinds 时，它的节点种类 token 用同一对号。带 kinds 的文档集合把字段名留在 0x02/0x03、把 kinds 放这里，于是两个分配者永不共享同一个 id 空间；kind 字段本身仍是普通载荷字段，配一条声明的索引。同一对号、同一条规则，谁需要谁用。

**"kind" 不是边的类型名——边的类型就是它的谓词。** "kind" 的信息量不比 "type" 多，而且行文里与节点的 kind（一个载荷字段）分不开。边的类型就是它的**谓词**：wire 上是 `predicate_id`，词汇表是 0x04/0x05，面是 0x08/0x09 的谓词面。边没有自己的号（ADR-0067），所以头部恰好是 `[src][pred][dst]`——谓词占据一个键维度，因为它是边的类型；身份是整个元组。

**Slot 布局与普通文档的关系**——明确说明，不追求严格一致：

- **节点 collection = 标准文档布局，不变。** 节点 kind 面不是新种类的 slot：它是计数族 0x1 里一个普通访问方法（固定本体形态是一条 `#[ok_index]` 声明，动态形态是用户分配的 `AccessMethod` slot）。节点 kind token 走 collection 自己那一对固定面（0x04/0x05，与图的谓词同一对号）——与它的 props 名所用的字段名词汇表（0x02/0x03）分开。与任何文档 collection 布局零差异；"某个字段是 kind"是建模约定，不是布局事实。
- **Edge collection = 上表那几类条目，用同一套 slot 词汇写成的另一种 collection 形态。** 0x01/0x02/0x03 保留文档侧含义（动态段、词汇表），0x00 空着（元组就是边的身份，所以没有主表行）；0x06–0x09 是图自己的面、0x04/0x05 是它自己的谓词词汇表，都落在固定面区间里——不引入新**种类**的 slot。值侧也不是第二套编码：边的载荷**就是**一份 obj（ADR-0012）。把它与文档 collection 区分开的是图的面与宽度由声明定死的端点，不是它自己的载荷格式。

- **边行（0x06）**：`[ns][0x06][src][pred][dst] -> 载荷`。元组是键、载荷是值，其中 `pred` 是**谓词**（边的类型），2 字节，来自图自己的谓词词汇表（0x04/0x05），也靠它按名字读回。值就是一份普通的 obj 载荷（ADR-0012）：`[热段][冷 TLV]`，与任何文档行同一套编码。遍历本来就要读这一行；没有边号之后，索引条目与行是同一条条目。
- **声明属性字段——必须显式声明**：src/dst/谓词之外的静态字段就是普通声明字段，配一条**显式**的访问方法声明（`#[ok_index(name { fields(…) })]`，与文档同一套词汇）：热/冷段摆放、生成的编码器**和**解码器、以及那条面（`[字段值][src][pred][dst]`，计数族 0x3nnn，按声明序）。不再为每个字段自动生成面——没人扫的字段由每条记录买单，节点侧早就这么定了（没有扫描者的面，跟着消费它的读路径一起落地）。一份声明、一套编解码、两个方向都生成，宽度住在声明里而不是每个消费方手里。这些条目用的边身份就是元组本身，所以索引条目以 `[src][pred][dst]` 收尾——与边自己的键同一批字节——并由同一条 `index_entries` 路径维护。过滤走该面的索引扫描、尾段即元组，而不是全量取边解码；字段值是边自身数据（不含 NodeRef），完全不触碰端点宽度。默认不建复合面（`谓词+字段`、`字段+端点`）——用选择度最高的面过滤，元组在内存收敛，与文档索引同一立场；复合面只在访问模式证明需要后再加。每条声明索引让一次写入与一次删除各多一条条目——写放大由声明者自选。
- **动态属性（固定面 0x01）**：边的开放属性就是这份 obj 的动态段——每条边**一条**条目 `[ns][0x01][src][pred][dst]`，nTLV 帧，字段名取词汇表号（ADR-0012）——即任何文档行都有的那个条目、那套编解码与 `replace_into`/`attrs` 面（ADR-0035）。该条目由图装配点持有（调用方不再手搓帧）。日后要查的开放属性走它声明好的 path 索引（ADR-0029——每个解析出的值一条条目，值类型限于有存储形态编码的那些），永远不靠加宽 key。全动态形态无需改动：声明为空，自由属性走同一 obj 形状。
- **节点侧 kind 过滤**：按节点 kind / 节点属性过滤是图查询的基本需求，按形态分别回答。固定本体形态下节点就是普通 document collection：节点"类型"= collection 本身（ns 即类型标记），属性过滤走 collection 自己的 `#[ok_index]` 声明索引——零新机制。全动态形态下节点 kind 是动态段数据，由两个既有机制承载过滤、不新增段：(1) **节点集合自己的词汇表**——带 kinds 的节点 collection 声明自己那一对（0x04/0x05，与图的谓词同一条规则），于是它的 kinds 永不与 props 的字段名（0x02/0x03）共享 id 空间，也与任何图的词汇天然分开（词汇表是 per-collection 的）。(2) **节点 kind 面**——节点 collection ns 内的一个声明访问方法，`[kind_id][node pkey]`，由节点正常 put 路径维护。复合过滤（`(*)-[谓词]->(:节点 kind)`）扫 0x08/0x09 面与节点 kind 面、内存求交 id 集合——两个便宜面、一次收敛（不为它建三元复合面）。
- **没有独立的谓词索引**：`[predicate_id]` 就是 0x08 的前缀，扫它即得一个谓词的全部边——`MATCH ()-[r:has]->()` 的入口——元组仍在尾段。`predicate_id` 来自**谓词词汇表**（0x04/0x05）：写入时 name → id，保证每个 key 段定宽可排序。这本词汇表同时是**列举面**：扫 0x04 就确切列出这张图的谓词，不必走遍历面去反推。
- **遍历（0x06/0x07）**：一个节点的全部出边 / 入边。被遍历那一端的 NodeRef 领先使扫描前缀可命中，谓词居中、另一端随后——于是一跳既知道去哪、也知道这条边是什么，且不读任何行；`(src, dst)` 在 0x06 上可寻址。
- **谓词过滤遍历（0x08/0x09）**：`(*)-[谓词]->(*)` 面——谓词领先，因为它在此面是过滤维度；它不能作为此面的尾段。
- **写入协议**：一次写入 = 0x06（含载荷）+ 0x07 + 0x08 + 0x09 + 每条**声明索引**一条计数族 0x3nnn 条目，一个 batch；调用方写过字段时，obj 的动态条目（固定面 0x01）同批写入。一张面一条条目，且没有主表行。**删除是精确删**：它读 0x06 那一行、按它持有的载荷重新生成声明面的条目、精确删掉它们——不对属性面做前缀扫。代价是删前多一次读，只在有解码器的地方付：动态形态需要它的 schema（以数据形式存在的、它自己的那份声明）才能把值读回，没有就退回前缀扫。与关系表的双写义务同构，按面数放大。

### 4. 一份声明，加一个不声明任何东西的句柄

声明**就是**这张图：

```text
#[derive(GraphEncode)]                     这张图的边集合
#[ok_ns(37)]                               图的 ns —— ns 的唯一来源
#[ok_nodes(EntityRow, MemberRow)]          成员集：节点**表**，按类型列出
#[ok_index(since { fields(since) })]       边的属性面，显式声明（§3）
pub struct Facts { … }                     图名即声明名；边的载荷 = 它的属性
```

一条 derive 就是一份声明：宏生成整个 `GraphEncode` impl（载荷编解码、声明的面、ns）、成员集枚举以及它的 `NodeSet` impl，`type Nodes` 绑定这个枚举。再手写 `impl GraphEncode for Facts { type Nodes = … }` 等于给同一个 trait 写第二个 impl——Rust 的关联类型也没有默认值可留白。

成员集是一个**类型**——枚举，一个变体指名一个节点 collection，于是"允许哪些节点"是代码里的编译期事实，而不是挂在载荷上的注记。属性列的是**表**（代码里一张表由它的文档类型命名），枚举由 derive 写出，所以一个成员的 ns 不会被写两遍：

```text
#[ok_nodes(EntityRow, MemberRow)]

// 生成：
pub enum FactsNode { EntityRow, MemberRow }   // 一个变体 = 一个 collection（一个 ns）
impl NodeSet for FactsNode {
    const NS_VALUES: &'static [u16] = &[36, 42];   // 各表自己的 #[ok_ns]
}
```

成员的单位是**集合**（它的 ns），不是文档类型——引用里带的就是那个号，所以成员判定在 ns 层（§2）。文档类型只是表在声明处的**名字**；图声明的成员集是一组**集合**，生成的变体不携带任何东西（没有访问器、没有 key 类型——ns 就是全部内容）。命名因此分两层：集合角色归 `NodeSet`（`NS_VALUES` 是全部成员的 ns），枚举本身取单数 `<图名>Node`——一个类型名命名一个值，一个值指名一个 collection，复数会让这个名字声称一件它的值域从不成立的事。

一张图 = 一份边声明（该图所有边共享）+ 一个生成的 `Node` 枚举（图名 + `Node`）+ 一个 ns。边与边的差别是谓词（运行期数据，走词汇表分配）；节点与节点的差别是枚举变体（编译期类型）。两者都由声明派生——没有手写表，也没有装配期声明。

**装配只是一个运行期句柄，仅此而已。** `Graph<S, E: GraphEncode>` 绑定一个引擎**实例**（同一份声明可挂到 mock、Fjall 或远端存储上——ADR-0025 的 one keyspace），以及无法住在类型里的每实例状态：词汇表缓存（谓词号分配的单写者纪律）。没有分配位置，因为没有身份要发。它不带 ns 参数（ns 来自 `E::NS_PREFIX`）、不带节点名单、不带 schema：装配点的声明内容为零。

- **固定本体**：上面那份声明用 Rust 写；节点集合就是普通文档集合，行就是普通文档。
- **全动态**（知识图谱）：**同一份**声明以数据形式携带——一个 `CollectionSchema` 值（静态侧用 `CollectionSchema::of` 导出，ADR-0025）加一个 okm-dynamic 句柄；空声明意味着只有身份、载荷全在动态段（声明 `props: Variant` 会把它放进 slot 0，那是静态形态——不是动态图想要的）。两种形态下谓词与自由属性都是词汇表数据；端点是宽度由声明定死的引用（§2）；遍历面通过动态层的 `AccessMethod` 构建走。动态句柄收的是声明给出的 **ns 与 schema 这一对**值，绝不是调用点自己编的裸 ns；当 ns 仍作为独立参数传入时（今天的 `DynamicCollection::new(store, ns, schema, …)`），由导出那一侧成对给出，装配时**拒绝**不一致，而不是覆盖。`CollectionSchema` 带 `ns_prefix`（声明自己的 `[ns 2B]`，于是"这一对"可比对）与 `members`（成员集，由 `CollectionSchema::of_graph::<E>()` 从 `E::Nodes::NS_VALUES` 导出）——这是图的声明里唯一无法用载荷布局表达的一半，也是动态写者会拿引用里的 ns 去校验的一半，与静态形态走 `E::Nodes` 完全同一件事。

两种形态共享同一 wire 布局与同一 slot 语义，且对同一份声明产出逐字节相同的字节：模式是**写入方**的属性，不是数据的（ADR-0025）。

### 5. 分类学中的位置（ADR-0015 §3）

三种关系载体，按两根轴划分——端点定类型与边的独立存在性：

```text
                    端点类型固定                  端点类型开放
单向                Refs<D, K>                   —
双向                Junction                     图 Edge
```

图 Edge 相对 Junction 的结构差异恰好两点，都被开放端点的要求逼出：端点是 `[ns 2B][pkey]` 的引用、宽度由声明定死，而非编译期定类型的 key；身份是元组 `(src, predicate, dst)` 而非一对身份，于是平行事实靠谓词分开，同一个谓词内的多值住在载荷里（ADR-0067）。其余一切——双写义务、条目面设计、ns 纪律——原样继承。语义上两者都是关系；图中的连接多出的是**属性**（它的 doc 半）与**方向**，并且独立于它所命名的端点而存在。

## 后果

- 声明是**图的声明**（`GraphEncode`）：一个 ns、边自己的载荷（复用文档编解码——没有第二套载荷编码）、它显式声明的属性面，以及一个 `Node` 枚举。图自己的面与写入协议住在 `Graph<S, E>` 句柄里，而句柄不声明任何东西——它是一个引擎实例加每实例状态。
- 成员节点集是编译期的（一个 `Node` 枚举）：不占 slot、不要注册表、没有运行期 `register()`。新增一种节点集合的代价是改代码——这是 ns 词汇表闭合（ADR-0002）的对价，也是知识图谱把运行期**类型**留在已声明集合里、而不是新建集合的原因。
- 图的形状跟随 PGQ：顶点表是声明的（`Node` 枚举），一张表可以既是顶点又是边，逐对的边类型不必要——一份声明服务所有对。
- 删除读 0x06 那一行、精确删掉声明字段的条目；动态形态为此需要它的 schema，否则退回前缀扫。
- 端点引用是 `[ns 2B][pkey]`、宽度取自声明的成员表，因此没有跨集合宽度注册表、键里也没有长度；端点的**类型**限制就是声明的 `Node` 枚举，写入期作为一次校验应用（§2）。
- ADR-0016 的 slot 分配不改动：0x06–0x09 是图自己的固定面，落在 Edge collection 的 ns 内（ADR-0030）。
- 尚无消费者。
