## 背景

关系分类学（ADR-0015 §3）有两种载体：`Refs<D, K>` 承载一对多（字段位、单向、固定父类型的孩子），`Junction` 承载多对多（独立条目、双物化、双端编译期定类型）。两者都把端点**编译期绑定到已声明的文档类型**——derive 解析 `<D as Document>::Key` 与 `NS_PREFIX`。

图应用打破这个绑定。知识图谱或 LLM 写入的属性图具有：

- **异构端点**——一个图连接多种类型的节点（Person、Org、Document……）；为每种端点类型组合声明一种 Edge 是组合爆炸。PGQ 把这条界线画在另一头，本 ADR 跟随它：属性图**声明**它的顶点表与每条边表的 SOURCE/DESTINATION 引用——一条边表可以引用多张顶点表，一张表也可以用不同别名同时当顶点和边——而每条边的节点**类型**是一份声明，不是每对一份。PGQ 禁止的（本 ADR 也禁止的）是**未声明的参与**。
- **运行期涌现的谓词**——边的谓词（"has"、"owns"），即它的类型，是数据：它走边集合自己的词汇表分配。节点**集合**恰好是反面：ns 词汇表是编译期闭合的（ADR-0002，"词汇表是代码"），所以知识图谱的节点是**已声明**集合的行（facts、entities、users 这样的集合），绝不是随手新建的集合；一个集合内部的节点"类型"是一个载荷字段。全动态形态下节点 kind 同理。
- **边的身份与属性**——平行边存在（同两节点间的两个 "has" 是两个事实），边携带动态属性。两种载体都不支持：Junction 的身份就是端点对，且两者都没有 per-edge 载荷。
- **独立存在**——边在查询范围内先于或后于端点文档存在；边集是一等集合，不是派生视图。

`Refs` 表达不了（孩子类型固定、字段位、单向、无属性）。`Junction` 也不行（端点类型固定、无边身份、无属性）。图 Edge 是**第三种关系载体**。

## 决策

### 1. Edge = 一等集合，每图一个 ns

一个图的边住在自己的 Edge collection——一个图的边集一个 ns，走正常 ns 词汇表分配（ADR-0002，"词汇表是代码"），与任何文档集合对称。无新命名空间机制：不是每种谓词一个 ns（动态形态下谓词是运行期数据），不是全局边池（图在 ns 层隔离），不是寄生（边独立于端点文档存在）。

同一个 ns 承载边集的所有条目种类，按 ADR-0016 的段号 slot 分派。

**成员节点集是声明，不是注册表（2026-10-17 更新）。** 一个图声明它可以有哪些集合充当节点——这是编译期事实，写在代码里，与它所依赖的 ns 词汇表放在一起（`Node` 枚举；§4）。它不占 slot：这个集合不带来任何运行期信息（每个候选集合本来就是一个编译期 ns），而一条元数据条目只会附赠"谁写、什么时候写、冲突算谁的"。运行期新建节点集合随之被否决：知识图谱的形状是**已声明**的集合、其行带类型字段——一个 ns 承载多种运行期类型——这比"每种涌现类型一个 ns"严格更便宜，也是唯一能保持 ns 词汇表闭合的读法（PGQ 自己的规矩：表要声明，不能凭空变）。

### 2. 自描述端点引用

端点**不是编译期定类型**。引用是 `[ns 2B BE][pkey]`——任意 collection 的任意文档、任意 key 形状。ns 充当类型标记：解码引用按 ns 路由到归属 collection，节点类型不受限。

pkey 的边界**不在 key 里**。一个 collection 的 pkey 宽度是 schema 事实（`KeyEncode::KEY_LEN`），Edge 实现通过 **ns → KEY_LEN 注册表**解析。三个候选方案经过权衡：

- **a. 定宽约定**——要求同一图内所有节点 collection 的 pkey 宽度相同（如都是 u64 id）。key 零开销，但对建模是硬约束：一个 20 字节复合键的异构节点就破坏它，且跨图复用注册表会变别扭。拒绝——对真实图太死板。
- **b. 自描述段（TLV）**——`[ns 2B][pkey_len varint][pkey]`。完全通用，任意 pkey 形状通用，解码无需注册表。代价：每条引用 +1 字节以上（len 前缀），且每次解码多一个 varint 步骤。拒绝——Edge collection 持有数千条引用，per-reference 开销会在遍历面（0x07-0x0A，存储中最高频的条目）上成倍放大。
- **c. 注册表查表（选中）**——pkey 宽度来自 schema（`KeyEncode::KEY_LEN`）；Edge 实现持有 **ns → KEY_LEN 注册表**（声明形态编译期生成，动态形态运行期表），按查找切出 pkey。key 零开销，把 Ref 纪律——"引用是 key 字节，ns 知识在声明处"——从单一绑定的端点类型推广到端点类型的注册表。注册表是新的跨集合 schema 事实：编译期形态生成，动态形态用户维护。

- **2026-09-20 更新——改选方案 b（自描述引用），方案 c 废弃。** 原草案对 b 的拒绝算错了账：共享 varint 编解码器把 pkey 宽度（4–16 字节）编进**单字节**，每条引用实付约 1 字节（遍历面 key 约 5%），不是"1 字节以上成倍放大"。与之相对，注册表的代价是全套：新的跨集合 schema 事实、`nodes(...)` 声明里手写宽度字面量与节点 key 的漂移风险、动态形态的运行期 `register()` 仪式，以及一个只为保卫注册表而存在的解码失败模式（未注册 ns）。引用变为 `[ns 2B][len varint][pkey]`——宽度是 wire 数据，遍历面依然精确前缀命中（同节点 = 同字节），两种形态的端点声明归零。Ref 纪律就此对图边**退役**：ns 知识不再住在声明点，而住在引用自身。

- **2026-10-17 更新——引用保持自描述，成员集是一次校验。** 引用在 wire 上仍是 `[ns 2B][len varint][pkey]`：脚本或 LLM 写入方没有 `Node` 枚举，引用必须能在没有它的情况下写出。声明的成员集在解码时应用（ns → 变体；越界即错误，绝不静默），写入时也应用（端点所属集合必须在声明里）。宽度仍来自引用自身——退役的那套注册表是**宽度**查表，成员集是**类型**限制：前者是 wire 数据，后者是声明。

### 3. Slot 分配（固定面与计数族，在 Edge ns 内）

```text
0x00  主表          [edge_id]
0x01  动态段        （边的开放属性）
0x02/0x03  字段名词汇表  （载荷自己的名字 ↔ 号）
0x04/0x05  谓词词汇表    （谓词名 ↔ predicate_id；本图的谓词）
0x06  谓词索引      [predicate_id]
0x07  出边          [src NodeRef][edge_id]
0x08  入边          [dst NodeRef][edge_id]
0x09  谓词正向      [predicate_id][src NodeRef][edge_id]
0x0A  谓词反向      [predicate_id][dst NodeRef][edge_id]
```
（图的面是固定面号——各一字节，ADR-0030；下文的声明属性面属于计数族 0x1。表里按**角色**排：两本词汇在前，读它们编号的面在后——词汇表排在它所服务的面之前；**编号**才是机制。）

**谓词有自己的一本词汇表（2026-10-17 更新）。** `[ns][0x04][predicate_id] → 谓词名`、`[ns][0x05][谓词名] → predicate_id`——与 0x02/0x03 同一双向形状，另一套词汇。于是"列出这张图有哪些谓词"就是扫一次 0x04 前缀：确切名单，永不靠走索引面反推。此前与载荷字段名共用一本，名字彼此分不开，"一个图里有哪些谓词"只能靠扫 0x06 推出来——而列举不该是推断。在同一本里按 id 号段切分被否，理由与本项目别处"结构分割优于前缀过滤"同类：号段是约定，第一次越界分配就静默失效；再加一对固定面是结构。代价：十六个固定面里用掉一对（0x04/0x05，ADR-0030；0x0C–0x0F 仍空（0x0B 归了 okm-vector 的索引快照）），边集合从此有两套词汇。字段名词汇表（0x02/0x03）对载荷自己的名字保留文档侧含义。

**这一对是图自己的谓词词汇表（2026-10-17 更新）。** 0x04/0x05 这对号也不是图专有的：它是集合在字段名**之外**自己的 token 词汇——这里是一张图的**谓词**；**节点集合**声明了 kinds 时，它的节点种类 token 用同一对号。带 kinds 的文档集合把字段名留在 0x02/0x03、把 kinds 放这里，于是两个分配者永不共享同一个 id 空间；kind 字段本身仍是普通载荷字段，配一条声明的索引。同一对号、同一条规则，谁需要谁用。

**"kind"作为"边的类型"的名字退役（2026-10-17 更新）。** 它的信息量不比"type"多，而且行文里与节点的 kind（一个载荷字段）分不开。边的类型就是它的**谓词**：wire 上是 `predicate_id`，词汇表是 0x04/0x05，面名是"谓词索引"/"谓词过滤遍历"。`edge_id` 考虑过并否决——那个名字是边自己的身份（主表键），用它命名头部第三段会让 `[src][dst][edge_id][载荷]` 读起来像在说这条边。

**Slot 布局与普通文档的关系（2026-09-20 更新）**——明确说明，不追求严格一致：

- **节点 collection = 标准文档布局，不变。** 节点 kind 面不是新种类的 slot：它是计数族 0x1 里一个普通访问方法（固定本体形态是一条 `#[ok_index]` 声明，动态形态是用户分配的 `AccessMethod` slot）。节点 kind token 走 collection 自己那一对固定面（0x04/0x05，与图的谓词同一对号）——与它的 props 名所用的字段名词汇表（0x02/0x03）分开。与任何文档 collection 布局零差异；"某个字段是 kind"是建模约定，不是布局事实。
- **Edge collection = 上表那几类条目，用同一套 slot 词汇写成的另一种 collection 形态。** 0x00/0x01/0x02/0x03 保留文档侧的含义（主表、动态段、词汇表）；0x06–0x0A 是图自己的面、0x04/0x05 是它自己的谓词词汇表，都落在固定面区间里——不引入新**种类**的 slot。值侧也不是第二套编码：边的载荷**就是**一份 obj（ADR-0012）。把它与文档 collection 区分开的是图的面与自描述端点，不是它自己的载荷格式。

- **主表（0x00）**：边本体——`[src NodeRef][dst NodeRef][predicate_id][obj 载荷]`，其中 `predicate_id` 是**谓词**（边的类型）作为 key 维度承载：2 字节，来自图自己的谓词词汇表（0x04/0x05），也靠它按名字读回。尾部区域就是一份普通的 obj 载荷（ADR-0012）：`[version u8][hot_len u16 BE][热段][冷 TLV]`，与任何文档行同一套编码。`src` / `dst` / `predicate_id` 是图自己的头部，载荷起始位置可算——引用自描述、`predicate_id` 定宽。
- **声明属性字段——必须显式声明（2026-10-17 更新）**：src/dst/谓词之外的静态字段就是普通声明字段，配一条**显式**的访问方法声明（`#[ok_index(name { fields(…) })]`，与文档同一套词汇）：热/冷段摆放、生成的编码器**和**解码器、以及那条面（`[字段值][edge_id]`，计数族 0x1，`0x1001+n`，按声明序）。不再为每个字段自动生成面——没人扫的字段由每条记录买单，节点侧早就这么定了（没有扫描者的面，跟着消费它的读路径一起落地）。这正是那套只有编码半的自造机制（`KvGraph::attrs`、`attr_faces`、`ATTR_SLOTS`，连同 `EdgeEncode` 的载荷 derive）手工做出来的形状，本条决策把它退役：一份声明、一套编解码、两个方向都生成，宽度住在声明里而不是每个消费方手里。这些条目用的边身份就是边自己的 key（`[edge_id u64]`，一个 `KeyEncode` newtype），所以索引条目照样以 edge_id 收尾，与原来的 attr 面同形，并由同一条 `index_entries` 路径维护。过滤走该面的索引扫描再解码回主表，而不是全量取边解码；字段值是边自身数据（不含 NodeRef），完全不触碰端点宽度。默认不建复合面（`谓词+字段`、`字段+端点`）——用选择度最高的面过滤，edge_id 在内存收敛，与文档索引同一立场；复合面只在访问模式证明需要后再加。每条声明索引使 link/unlink 多写一条条目——写放大由声明者自选。
- **动态属性（固定面 0x01）**：边的开放属性就是这份 obj 的动态段——每条边**一条**条目 `[ns][0x01][edge_id]`，nTLV 帧，字段名取词汇表号（ADR-0012）——即任何文档行都有的那个条目、那套编解码与 `replace_into`/`attrs` 面（ADR-0035 改名）。该条目由图装配点持有（调用方不再手搓帧）。日后要查的开放属性走它声明好的 path 索引（ADR-0029——每个解析出的值一条条目，值类型限于有存储形态编码的那些），永远不靠加宽 key。全动态形态无需改动：声明为空，自由属性走同一 obj 形状。
- **节点侧 kind 过滤（2026-09-20 更新）**：按节点 kind / 节点属性过滤是图查询的基本需求，按形态分别回答。固定本体形态下节点就是普通 document collection：节点"类型"= collection 本身（ns 即类型标记），属性过滤走 collection 自己的 `#[ok_index]` 声明索引——零新机制。全动态形态下节点 kind 是动态段数据，由两个既有机制承载过滤、不新增段：(1) **节点集合自己的词汇表**——带 kinds 的节点 collection 声明自己那一对（0x04/0x05，与图的谓词同一条规则），于是它的 kinds 永不与 props 的字段名（0x02/0x03）共享 id 空间，也与任何图的词汇天然分开（词汇表是 per-collection 的）。(2) **节点 kind 面**——节点 collection ns 内的一个声明访问方法，`[kind_id][node pkey]`，由节点正常 put 路径维护。复合过滤（`(*)-[谓词]->(:节点 kind)`）扫 0x04/0x05 面与节点 kind 面、内存求交 id 集合——两个便宜面、一次收敛（不为它建三元复合面）。
- **谓词索引（0x06）**：一个谓词的全部边——`MATCH ()-[r:has]->()` 的入口。`predicate_id` 来自**谓词词汇表**（0x04/0x05）：写入时 name → id，保证每个 key 段定宽可排序。这本词汇表同时是**列举面**：扫 0x04 就确切列出这张图的谓词，不必走这张索引面去反推。
- **遍历（0x07/0x08）**：一个节点的全部出边 / 入边。完整 NodeRef 领先使扫描前缀可命中；`edge_id` 收尾——平行边（同两节点间的两个事实）各得一条条目，尾段 id 解码回主表。
- **谓词过滤遍历（0x09/0x0A）**：`(*)-[谓词]->(*)` 面——谓词领先，因为它在此面是过滤维度；它不能作为此面的尾段。
- **写入协议**：`link` = 主表 + 每条**声明索引**一条计数族 0x1 条目 + 0x06 + 0x07 + 0x08 + 0x09 + 0x0A，一个 batch；调用方写过字段时，obj 的动态条目（固定面 0x01）同批写入。**`unlink` 精确删（2026-10-17 更新）**：它解码边本体、取出声明字段的值、精确删掉那些条目——不对属性面做前缀扫。代价是删前多一次读，只在有解码器的地方付：动态形态需要它的 schema（以数据形式存在的、它自己的那份声明）才能把值读回，没有就退回前缀扫。与 Junction 的双写义务同构，按面数放大。

### 4. 一份声明，加一个不声明任何东西的句柄

声明**就是**这张图（2026-10-17 更新）：

```text
#[derive(GraphEncode)]                     这张图的边集合
#[ok_ns(37)]                               图的 ns —— ns 的唯一来源
#[ok_nodes(EntityRow, MemberRow)]          成员集：节点**表**，按类型列出
#[ok_index(since { fields(since) })]       边的属性面，显式声明（§3）
pub struct Facts { … }                     图名即声明名；边的载荷 = 它的属性
```

一条 derive 就是一份声明：宏生成整个 `GraphEncode` impl（载荷编解码、声明的面、ns）、成员集枚举以及它的 `NodeSet` impl，`type Nodes` 绑定这个枚举。再手写 `impl GraphEncode for Facts { type Nodes = … }` 等于给同一个 trait 写第二个 impl——Rust 的关联类型也没有默认值可留白。

成员集是一个**类型**——枚举，一个变体指名一个节点 collection，于是"允许哪些节点"是代码里的编译期事实，而不是挂在载荷上的注记。属性列的是**表**（代码里一张表由它的文档类型命名），枚举由 derive 写出，所以一个成员的 ns 不会被写两遍：

```text
#[ok_nodes(EntityRow, MemberRow)]

// 生成：
pub enum FactsNode { EntityRow, MemberRow }   // 一个变体 = 一个 collection（一个 ns）
impl NodeSet for FactsNode {
    const NS_VALUES: &'static [u16] = &[36, 42];   // 各表自己的 #[ok_ns]
}
```

成员的单位是**集合**（它的 ns），不是文档类型——引用里带的就是那个号，所以成员判定在 ns 层（§2）。文档类型只是表在声明处的**名字**；图声明的成员集是一组**集合**，生成的变体不携带任何东西（没有访问器、没有 key 类型——ns 就是全部内容）。命名因此分两层：集合角色归 `NodeSet`（`NS_VALUES` 是全部成员的 ns），枚举本身取单数 `<图名>Node`——一个类型名命名一个值，一个值指名一个 collection，复数会让这个名字声称一件它的值域从不成立的事。

一张图 = 一份边声明（该图所有边共享）+ 一个生成的 `Node` 枚举（图名 + `Node`）+ 一个 ns。边与边的差别是谓词（运行期数据，走词汇表分配）；节点与节点的差别是枚举变体（编译期类型）。两者都由声明派生——没有手写表，也没有装配期声明。

**装配只是一个运行期句柄，仅此而已。** `Graph<S, E: GraphEncode>` 绑定一个引擎**实例**（同一份声明可挂到 mock、Fjall 或远端存储上——ADR-0025 的 one keyspace），以及无法住在类型里的每实例状态：词汇表缓存（谓词号分配的单写者纪律）与 edge_id 分配位置。它不带 ns 参数（ns 来自 `E::NS_PREFIX`）、不带节点名单、不带 schema：本决策之后，装配点的声明内容为零。

- **固定本体**：上面那份声明用 Rust 写；节点集合就是普通文档集合，行就是普通文档。
- **全动态**（知识图谱）：**同一份**声明以数据形式携带——一个 `CollectionSchema` 值（静态侧用 `CollectionSchema::of` 导出，ADR-0025）加一个 okm-dynamic 句柄；空声明意味着只有身份、载荷全在动态段（声明 `props: DynamicValue` 会把它放进 slot 0，那是静态形态——不是动态图想要的）。两种形态下谓词与自由属性都是词汇表数据；端点是自描述引用（§2）；遍历面通过动态层的 `AccessMethod` 构建走。动态句柄收的是声明给出的 **ns 与 schema 这一对**值，绝不是调用点自己编的裸 ns；当 ns 仍作为独立参数传入时（今天的 `DynamicCollection::new(store, ns, schema, …)`），由导出那一侧成对给出，装配时**拒绝**不一致，而不是覆盖。**2026-10-19 落地：** `CollectionSchema` 现在带 `ns_prefix`（声明自己的 `[ns 2B]`，于是"这一对"可比对）与 `members`（成员集，由 `CollectionSchema::of_graph::<E>()` 从 `E::Nodes::NS_VALUES` 导出）——这是图的声明里唯一无法用载荷布局表达的一半，也是动态写者会拿引用里的 ns 去校验的一半，与静态形态走 `E::Nodes` 完全同一件事。

两种形态共享同一 wire 布局与同一 slot 语义，且对同一份声明产出逐字节相同的字节：模式是**写入方**的属性，不是数据的（ADR-0025）。

### 5. 分类学中的位置（ADR-0015 §3 修订）

三种关系载体，按两根轴划分——端点定类型与边的独立存在性：

```text
                    端点类型固定                  端点类型开放
单向                Refs<D, K>                   —
双向                Junction                     图 Edge
```

图 Edge 相对 Junction 的结构差异恰好两点，都被开放端点的要求逼出：端点是自描述引用（`[ns 2B][len varint][pkey]`）而非编译期定类型的 key；尾段是 `edge_id`（而非对端身份），因为平行边存在。其余一切——双写义务、条目面设计、ns 纪律——原样继承。语义上两者都是关系；图中的连接多出的是**属性**（它的 doc 半）与**方向**，并且独立于它所命名的端点而存在。

## 后果

- 声明是**图的声明**（`GraphEncode`）：一个 ns、边自己的载荷（复用文档编解码——没有第二套载荷编码）、它显式声明的属性面，以及一个 `Node` 枚举。`EdgeEncode` 与那套只有编码半的属性机制（`attrs()` / `attr_faces()` / `ATTR_SLOTS`）随之退役。图自己的面与六条条目的写入协议住在 `Graph<S, E>` 句柄里，而句柄不声明任何东西——它是一个引擎实例加每实例状态。
- 成员节点集是编译期的（一个 `Node` 枚举）：不占 slot、不要注册表、没有运行期 `register()`。新增一种节点集合的代价是改代码——这是 ns 词汇表闭合（ADR-0002）的对价，也是知识图谱把运行期**类型**留在已声明集合里、而不是新建集合的原因。
- 图的形状跟随 PGQ、而不是草案对它的读法：顶点表是声明的（`Node` 枚举），一张表可以既是顶点又是边，逐对的边类型不必要——一份声明服务所有对。
- `unlink` 读边本体、精确删掉声明字段的条目；动态形态为此需要它的 schema，否则退回前缀扫。
- 端点引用自描述（`[ns 2B][len varint][pkey]`），因此没有跨集合宽度注册表；端点的**类型**限制就是声明的 `Node` 枚举，作为一次校验应用（§2）。
- ADR-0016 的 slot 分配不改动：0x06–0x0A 是图自己的固定面，落在 Edge collection 的 ns 内（ADR-0030）。
- 尚无消费者；设计在 `#[ok_relation]` 工作开始前落档，因为两者共用写路径 diff 机制。（更新 2026-09-20：`#[ok_relation]` 字段位形态随后被否决——见 ADR-0015 未来工作 §B；junction 的命令式 link/unlink 成对操作确立，本 ADR 的 put 路径 `link_into` batch 面不受影响。）
