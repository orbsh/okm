# ADR-0079：热路径携带它已经造好的东西

**Status**：2026-11-21 裁决，同日以两个提交落地（`62c3cbf` 是表头，`24f80ef` 是 plan 与条目缓冲）。PLAN 无对应阶段。同一想法的第三块——一个 `Entries` 缓冲、一个生产者——归 ADR-0076，这里不重复认领。

typed 路径上的一次写，在碰到引擎之前做三件事：造 key、找这张表的路由、造条目。这三件在以前都是**每次调用**重新构造一个自句柄构造以来就没有变过的东西。没有一件是设计决定，都是代码碰巧长成的形状，而三件都站在每一次写都要付的那条路上。

## 背景

**key 表头。** `header()` 以前答 `Vec<u8>`：分区前缀（缺席，或 `[0xFF][id]`）再接 ns 两字节大端，每次调用现拼。句柄的 ns 在构造之后不会变——`with_ns` 与 `rebased` 造的是另一个句柄——所以这个答案对句柄的整个生命周期是固定的，可每一处造 key 的地方还是为它付一次分配。

**路由。** plan（ADR-0076）说这张表的 key 与条目长什么样，日志每次提交都需要它来判断一个 key 是否属于它要捕获的表。在 plan 变成静态量之前，日志靠比对自己持有的表头来回答——每次提交都做一遍随表数量增长的工作。

**条目。** ADR-0076 §1 已覆盖：plan 成为唯一条目生产者，追加进一个复用的 `Entries` 缓冲，而不是返回 owned 对。这篇 ADR 记录的是那个 plan 住在哪里，因为正是这个答案让另外两件变便宜。

## 裁决

**1. 句柄携带自己的表头。** `[u8; 16]` 加一个长度，构造时由 `assemble_header` 一次填好（没有 override 时原样用声明自己的 `NS_PREFIX`，所以不声明 ns 的文档写下的字节与以前一字不差）。`header()` 答指向这块缓冲的 `&[u8]`。容量取十六而不是声明真正能发出的四（`[0xFF][id]` 加两字节），是为了让未来的前缀不可能被静默截断；调用方看到的只有长度。

二十六个只读的调用点不再分配；八个要改的写 `to_vec()`，并且就是这个意思。warm 写路径的分配计数（`okm-core/tests/alloc_test.rs`，上限重新钉过）：typed put 18 → 15、merge 48 → 44、purge 22 → 19。`primary_key` 也改成在一个缓冲里拼完，而不是先造三字节表头再越过它增长。ephemeral 引擎上带索引与 reduce 的 `put`：1.3571 → 1.3081 µs。

**2. plan 是声明拥有的静态量，日志把它放在原本就按表持有的段元数据旁边。** derive 为每个 ns 发出 `static __OKM_NS_{ns}_ENTRY: OnceLock<TablePlan>`；`Document::PLAN` 是指向它的 `&'static`；attach 用 `get_or_init` 一次填好（声明的纯函数）。日志把这个引用存进它按已知表持有的记录里，于是表不可能"只知道一半"——有表头没 plan，或有 plan 没目录。一次提交之后问 `plan.carries_key(key)`：剥掉表头，测一个位。路由成本是常数，不随 store 里的表数量增长。

这个静态量发在声明旁边而不是泛型代码内部，是因为泛型作用域里的静态量是每个实例化一份——存储必须待在声明所在的地方，越过泛型边界的只有一个指针。

同一个静态量也是"一个 ns 一张表"的编译期那一半：同一模块里两个声明抢一个 ns，就是同一个名字定义两次，编译器拒绝它（`the name __OKM_NS_7_ENTRY is defined multiple times`）。

## 被否

**表头继续用 `Vec<u8>`。** 每次造 key 一次分配，而答案在构造时就固定了。要改的地方只有八处，且每一处本来就在有意复制字节，所以在那里写 `to_vec()` 比到处返回 `Vec` 更能说明意图。

**句柄上放 `Vec` 字段而不是内联数组。** 分配只是从每次读搬到构造一次，而每次造 key 仍然多一层堆间接。内联数组拷也免费、读也免费。

**按 collection 编译或缓存 plan。** ADR-0076 的否法仍然成立：缓存等于把 plan 存在的意义要消掉的那次查表装回写路径。静态量不是缓存——它是每进程每个 ns 一个值，由唯一知道怎么造它的代码填。

**给日志另存一份 plan。** 一张表两个真相，而第二个要在第一个更新时同步。

## 后果

句柄的表头是它持有的值，所以 `Collection` 连同表头一起克隆，也没有任何调用方能观察到表头在自己的脚下改变。`with_ns` 与 `rebased` 产生的是各自拼表头的新句柄。

plan 的身份是 ns，所以共用一个 ns 的两个声明共用一个静态量——这就是 `#[ok_shared_ns_in_tests]` 干脆不发那个声明的原因，也是 attach 在 meta 行（而不是在静态量上）拒绝被另一份声明盖过章的 store 的原因。

任何需要"声明并不拥有的 plan"的地方——动态形态，声明是从 store 的 meta 行读出来的——仍然自己调 `TablePlan::compile` 并自己持有结果。静态量是 typed 路径的优化，不是第二套机制。
