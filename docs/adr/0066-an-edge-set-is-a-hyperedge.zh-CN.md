# ADR-0066：一簇边就是一条簇

**状态**：草稿（2026-11-12）。合并 `docs/ideas/hyperedge-membership.md` 与被采纳的 `docs/ideas/hypergraph.md` 部分；取代后者的成员面布局——本 ADR 是它的推广。

本文用「簇」称呼它，文献里叫 hyperedge；区别只在于我们并不用它那套 arity 理论。社区（LPA）是簇的一种——成员是算出来的，不是声明的。

## 背景

图携带的是二元边：一条事实是 `(源, 目的, 谓词, 载荷)`。有些知识不是二元的——一个社区、一次事件的全部证据、一个子图、一条权限边界——它们是**一簇被命名的断言**。形状只有两种选择：给这组东西一个节点，把成员挂在它下面（星形／具体化节点）；或者让这组东西就住在表里，用它自己的行指向成员。

星形形状会丢掉模型需要的东西：顶点集相同而边集不同的两组无法区分；一条边被两组共享这件事看不见；边自己的角色没有位置；而那个伪节点会变成高连接度的假枢纽，社区发现会把它读成核心。而底图本来就是完整的——分组是它上面的一层组织，不是对它的改动。

## 决定

**1 一簇边是若干行，不是一个节点。** 成员住进同一种行型，一个成员一行：

```text
0x0A  簇本身（权威）   [ns][0x0A][kind][hyper_id]           → [parent_id u64 BE][动态载荷]
0x0B  边成员（权威）   [ns][0x0B][kind][hyper_id][edge_id]  → 空
0x0C  子簇索引（派生） [ns][0x0C][kind][父簇号][hyper_id]   → 空，可重建
```

`kind` 是一字节的闭合词表（社区／事件／子图／作用域）；`hyper_id` 运行时分配，不按声明序。**面就是行型**——不在行内再分一层字节——而 `kind` 留在键里，于是同一个面服务所有词表。成员行不带值：值在边上。成员按边号有序出来，这是存储唯一承诺的顺序。

**2 成员是边；参与者是它们的端点。** 边行本来就带两端，所以一个簇的节点就是它成员边的端点，去重即可。但这次投影住在存储**之外**：没有派生的节点面。需要参与者的人自己取成员边，在本地排序或去重——插进有序表是 log n，不需要 HashMap。反过来，一个镜像端点的面要为每条被分簇的边多写一行，而节点类型是异质的，维护这条镜像的代价大于它省下的。

**3 完备性靠一条写入前提，不靠补行。** 节点只在成为某条边的端点时存在（没有"单独建节点"这条路径）；簇只在有两个以上成员时创建。这两条成立时，不需要"没有边的成员"这种形状，读者从成员边推出的端点也总是真的。

**4 簇自己就是一行，键比成员短一级。** `[ns][0x0A][kind][hyper_id]` 放载荷——成员数、权重、最近写入时间——而成员在 `0x0B`，自己一张面。这与词表游标 `[ns][0x02]` 同形（69197cd），差别只有一处且要紧：游标的条目与它同面，扫描必须限定键长才不会把游标读成条目；这里面前缀不同，不需要任何长度判断。列某类簇是 `[ns][0x0A][kind]`，列某条簇的成员是 `[ns][0x0B][kind][簇号]`——两次扫描，各自无歧义。值是**定长头 + 动态尾**：`[parent_id u64 BE][载荷]`。`parent_id` 定宽且排在最前，读者不用解码任何东西就能切片；`0` 表示没有父簇——是保留值而不是可空标志，所以头永远是八字节。于是簇的嵌套走簇行自身，不需要第二个面。代价写明白而不是藏起来：读一个簇的父是免费的，列一个簇的子则是扫 `[ns][0x0A][kind]`，除非加上下面那条派生面——而它已经加了。载荷是动态段那套形状（`Dict`），因为 `kind` 是运行时词表，没有对应的声明类型。

**5 分组带版本；删除是写路径契约。** 重算写一个新版本，旧版本保留，于是 diff 与回滚都是普通集合运算。删一条边时，它的成员行在同一批里删除；漏删是新鲜度问题而不是正确性问题，因为子簇索引能从簇行重建。

**6 底图保持干净。** 算法（最短路、PageRank、连通分量、社区发现）只在边表上跑，永远看不到分组。于是"忽略跨簇边"不是妥协，而是模型对"图有模块结构"这一事实的利用。收缩与展开——把边分簇、簇内计算、簇间计算——就是一次 `group by` 加一次 `join`，不需要任何图重构。残差（不属于选中簇的边）必须可查询；误差是不对称的：度类指标容忍截断，路径类不容忍。

**7 一个写入口，不新增声明。** `Decl` 永远两个变体；"多种节点"由 `#[derive(GraphEncode)]` 为 `#[ok_nodes(…)]` 生成的枚举表达（一个变体一个集合，ns 取自各表自己的 `#[ok_ns]`）：

```rust
let mut fragment = Fragment::<G>::new([Decl::Node(G::Nodes::User, key), Decl::Edge(head), …]);
fragment.cluster(Cluster { kind, id, payload })         // id None = 新建，Some = 合并
 .on_node_conflict::<User>(|old, _declared| User { seen: old.seen + 1 })   // 按集合注册：节点行是异质的
 .on_edge_conflict(|_stored, declared| E { weight: declared.weight + 1 })  // 一张图只有一种边载荷
 .on_cluster_conflict(|_stored, declared| declared.clone());                // 簇是动态的
graph.incorporate(fragment);                            // 端点、边、成员行、三个冲突钩子

// 只有声明是必须的：什么都不挂的碎片，就只写节点与边
graph.incorporate(Fragment::new([Decl::Node(G::Nodes::User, key)]));
```

端点按需创建；成员加入幂等（同一 `(kind, 簇, 成员)` upsert）；三个冲突钩子在同一批里求值——ADR-0028 的计数器就落在这里。每个钩子拿到**已存**载荷与**声明**载荷，回答要写入的那一行，于是「保留」「覆盖」「取最新的 stamp」各自是一个表达式。其余操作复用同一行型：`remove`、`incorporate`、`split`、`reassign`、`lookup`、`members`、`diff`。

**8 四条固定面，取自核心带腾出的位置。** `0x0A` 簇行、`0x0B` 边成员、`0x0C` 派生的子簇索引 `[ns][0x0C][kind][父簇号][子簇号]`——它把"列一个簇的子簇"变成干净的前缀扫，自己由簇行里的 `parent_id` 派生，扫一遍簇行即可重建。`0x0D` 派生的一边→簇索引 `[ns][0x0D][边号][kind][簇号]`，同一次成员关系的另一个方向：`0x0B` 答"这个簇里有谁"，`0x0D` 答"这条边在哪些簇里"，且只由成员行派生。用四张面而不是「一张面加行内字节」，因为模型的规矩是**面说明这一行是什么**。新的行型进 `0x0E` Extension，带内用子类号。簇不用计数族：计数族的计数器是声明序、上限 4095，而簇是运行时无界的。

这个反向索引为什么值得一张面，以及为什么 `边号` 领衔：一条边属于哪些簇，否则只能靠 `0x0B` 的**后缀**扫（收回路径正是这么做的），那就把该 kind 的成员行全部看一遍——每次收回一次还好，每次遍历一跳都这么做就不行了。`0x0D` 把同一个问题变成一次前缀扫，而边号领衔让它的条目按「边号流本来就有的顺序」排，于是「这些节点指向的边中，哪些是 C 的成员」是两条有序流之间的一次 `intersect_seek`，而不是调用方自己先攒一个集合。它是派生，不是真相：每次 add / remove / 收回都与 `0x0B` 的行同批写入，在变更日志里归为 Derived，并由 `rebuild_derived` 只凭 `0x0B` 重建。

## 后果

- 一条事实可以属于多个簇，拓扑完全不动。
- "这个簇里有什么"与"两个版本之间变了什么"是扫描与集合运算，不是遍历。
- 存储上每条被分簇的边多出一行（成员行）；子簇索引是每条嵌套关系一行、不是每个成员一行。要盯的数是"每条边平均属于几簇"。
- 任何重算都必须写版本而不是覆盖；读者看到的始终是某一个版本的一致快照。

## 被否

- **一簇一个节点（星形／具体化）。** 丢集合身份、丢共享成员、丢边自身角色，还用假枢纽污染算法。
- **一簇一个计数族槽位。** 上限 4095 且语义是"声明序"——对运行时簇是错的。
- **把集合存成一个值。** 集合值的条目就是跨行读-改-写，写入契约不允许。
- **另一个超图声明种类。** 图已经声明了成员；上面那个写入口就是全部新增。
