# ADR-0066：一组边就是一条超边

**状态**：草稿（2026-11-12）。合并 `docs/ideas/hyperedge-membership.md` 与被采纳的 `docs/ideas/hypergraph.md` 部分；取代后者的成员面布局——本 ADR 是它的推广。

## 背景

图携带的是二元边：一条事实是 `(源, 目的, 谓词, 载荷)`。有些知识不是二元的——一个社区、一次事件的全部证据、一个子图、一条权限边界——它们是**一组被命名的断言**。形状只有两种选择：给这组东西一个节点，把成员挂在它下面（星形／具体化节点）；或者让这组东西就住在表里，用它自己的行指向成员。

星形形状会丢掉模型需要的东西：顶点集相同而边集不同的两组无法区分；一条边被两组共享这件事看不见；边自己的角色没有位置；而那个伪节点会变成高连接度的假枢纽，社区发现会把它读成核心。而底图本来就是完整的——分组是它上面的一层组织，不是对它的改动。

## 决定

**1 一组边是若干行，不是一个节点。** 成员住进同一种行型，一个成员一行：

```text
0x0A  边成员（权威）    [ns][0x0A][kind][group_id][edge_id]
0x0B  节点成员（派生）  [ns][0x0B][kind][group_id][node_id][edge_id]
```

`kind` 是一字节的闭合词表（社区／事件／子图／作用域）；`group_id` 运行时分配，不按声明序。**面就是行型**——不在行内再分一层字节——而 `kind` 留在键里，于是同一个面服务所有词表。成员是有序出来的：`0x0A` 按边号、`0x0B` 按节点号——后者让"这个组的成员"成为一条可流式的流，重复只会相邻出现，于是去重是一次比较而不是一个集合。

**2 成员是边；节点成员是派生的。** 边行本来就带两端，所以一个组的节点就是它成员边的端点，去重即可。`0x0B` 只做两件事：把这次投影变成**有序可流式**，以及顺带给出计数。它任何时候都能从 `0x0A` 与边行重建——是一条索引，不是第二份真相。

**3 完备性靠一条写入前提，不靠补行。** 节点只在成为某条边的端点时存在（没有"单独建节点"这条路径）；组只在有两个以上成员时创建。这两条成立时，导出法是完备的，也就不需要"没有边的成员"这种形状。

**4 组有动态载荷。** 它不是纯集合：成员数、权重、最近写入时间都放在组上。它不能是声明的 Rust 类型，因为 `kind` 是运行时词表，所以载荷就是动态段那套形状（`Dict`）。

**5 分组带版本；删除是写路径契约。** 重算写一个新版本，旧版本保留，于是 diff 与回滚都是普通集合运算。删一条边时，它的成员行在同一批里删除；漏删是新鲜度问题而不是正确性问题，因为 `0x0B` 可重建。

**6 底图保持干净。** 算法（最短路、PageRank、连通分量、社区发现）只在边表上跑，永远看不到分组。于是"忽略跨组边"不是妥协，而是模型对"图有模块结构"这一事实的利用。收缩与展开——把边分组、组内计算、组间计算——就是一次 `group by` 加一次 `join`，不需要任何图重构。残差（不属于选中组的边）必须可查询；误差是不对称的：度类指标容忍截断，路径类不容忍。

**7 一个写入口，不新增声明。** `Decl` 永远两个变体；"多种节点"由 `#[derive(GraphEncode)]` 为 `#[ok_nodes(…)]` 生成的枚举表达（一个变体一个集合，ns 取自各表自己的 `#[ok_ns]`）：

```rust
Vec::<Decl<G>>::new()
    .decls([Decl::Node(G::Nodes::User, key), Decl::Edge(head), …])
    .hyper_edge(HyperEdge { kind, id, payload })        // id None = 新建，Some = 合并
    .reduce_node::<User>(|u: &mut User| u.seen += 1)    // 按集合注册：节点行是异质的
    .reduce_edge(|e: &mut E| e.weight += 1)             // 一张图只有一种边载荷
    .reduce_hyper_edge(|h: &mut Dict| …)                // 组是动态的
```

端点按需创建；成员加入幂等（同一 `(kind, 组, 成员)` upsert）；三个 reduce 在同一批里求值——ADR-0028 的计数器就落在这里。其余操作复用同一行型：`remove`、`merge`、`split`、`reassign`、`lookup`、`members`、`nodes`、`diff`。

**8 两条固定面，取自核心带腾出的位置。** `0x0A` 与 `0x0B`——连续，正是向量快照搬走后腾出的头两个号。用两条面而不是「一条面加一个行内字节」，因为模型的规矩是**面说明这一行是什么**；`0x0C`、`0x0D` 仍空闲。组不用计数族：计数族的计数器是声明序、上限 4095，而组是运行时无界的。

## 后果

- 一条事实可以属于多条组，拓扑完全不动。
- "这个组里有什么"与"两个版本之间变了什么"是扫描与集合运算，不是遍历。
- 存储上每条被分组的边大约多出三行（两条派生节点行 + 一条成员行）；要盯的数是"每条边平均属于几组"。
- 任何重算都必须写版本而不是覆盖；读者看到的始终是某一个版本的一致快照。

## 被否

- **一组一个节点（星形／具体化）。** 丢集合身份、丢共享成员、丢边自身角色，还用假枢纽污染算法。
- **一组一个计数族槽位。** 上限 4095 且语义是"声明序"——对运行时组是错的。
- **把集合存成一个值。** 集合值的条目就是跨行读-改-写，写入契约不允许。
- **另一个超图声明种类。** 图已经声明了成员；上面那个写入口就是全部新增。
