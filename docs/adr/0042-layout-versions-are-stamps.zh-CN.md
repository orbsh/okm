# 0042 — 布局版本是戳记，不是兼容承诺

> **语言：** [English](0042-layout-versions-are-stamps.md)（主） · [中文](0042-layout-versions-are-stamps.zh-CN.md)

**状态：** Accepted（2026-10-27）。同日应用：k10r 的 `EntityRow` 回到 `version = 1`，
使用计数挪到**前面**——读者会去找它们的位置。2026-10-28 细化：号可以直接递增（重置本来
就不是要点），并补上「什么才真正挣得兼容」。
**日期：** 2026-10-27，2026-10-28 细化

## 背景

payload 带一个版本字节，解码器有一条兼容规则：比读者新的 payload 拒绝，比读者旧的接受、
缺失的字段取默认值。这条机制是对的，而它也是块磁铁：一旦 codec 能吞掉形状变化，
形状变化就会开始**绕着它**设计。

在这条记录之前，有两处是那么写的。

- 实体行的使用计数被追在**尾部**，「因为尾部追加是唯一合法的加字段方式」——这是 codec
  决定了字段该放哪。读者去找一个节点的计数，会在 `name` 之后、在结构体本该放残渣的那一段里
  找到它。
- 删掉一个字段（向量，ADR-0019）让后面每个帧都移位，于是每个已有 store 都要重建——而这个
  重建变成了一段 ADR 里的论证，仿佛一个从没存过生产数据的记忆核心，欠它自己的临时目录一条
  升级路径。

## 裁决

**1. 版本字节是一枚戳记。** 它记录 payload 是按哪个形状写的。它不是「别的构建能读它」的承诺。

**2. 号可以直接递增，这是常规写法。** 形状变了就给这张表一个新号——递增是默认做法，重置回 1
同样合法（一张没有历史需要区分形状的表、一份本来就要重生成的语料）。号只有一个职责：两个
不兼容的形状必须能被**署名区分**。它不是阶梯，版本 N+1 没有义务读得懂版本 N 的字节。

**3. 字段放在它该在的地方。** 声明顺序为**读者**而选——身份在前，读会碰到的其次，残渣最后——
绝不为 codec 追加方便而选。

**4. 没有哪张表欠一个兼容解码器。** 读旧形状是按表、**写进记录**的决定（某条记录写明「这些
payload 必须活过形状变化」并说明理由）。沉默的含义是 store 重生成，或走迁移——从来不是
「新构建替旧形状保留一个解码器」。

**5. 迁移是导出 → 导入，不是双版本读取器。** 写下数据的那版构建把读得到的行导出；接手的那版
构建按自己的布局导入。bundle 与按表 Parquet 导出已经存在、装的是调用方自己的行、有归属方。
原地「读时升级」（旧记录留在旧格式里）不是本设计。

**6. 解码规则维持原样——它是失败模式，不是迁移策略。** 更新的 payload 拒绝、更旧的取默认，
这是旧 store 被打开时「大声失败或落得合理」的保障。默认值不是「字段可以缺席」。

**7. 什么才真正挣得兼容——以及生产升级到底怎么做。** 付得起这笔账的场景：生产数据不能丢，
且大到导入导出窗口不可接受。答案仍不是宽容的解码器，而是**蓝绿迁移**：新构建作为第二个进程、
配自己的 store 起来；旧实例导出、新实例导入——回填可以跑几小时几天，这期间两边都在线——然后
为增量追平停一个短窗口，把流量切到新实例。体量真正成为问题的那一半，由冷数据一侧的
lakehouse／对象存储导出承担（或换成自己拥有落盘格式的引擎，slatedb 一类），回填因此是批量装载，
而不是逐行走写路径重灌。

两个构建永远不共用同一个 store——KV 是单写的——所以哪怕这次升级一个字节格式都不改，也要
停-换。这是相对 SQL 的结构性劣势。实际影响比看起来小：一两秒的
停机落在用户本来就归咎于网络的延迟区间里；网关层加一条重试策略，请求根本不会以失败的形式
露出来；按流量预测挑一个无人访问的窗口做切换——连军事装备都有维护窗口。SQL 在纸面上确实
更占优，这点得承认：DDL 允许在线改结构，无缝升级在理论上成立。难点不在引擎而在**应用层**——
多环境测试、上线前先做快照、还要备一套回滚预案。所以论开发，SQL 在升级这条轴上明显领先；
论生产，优势比看起来小得多。看起来无缝就够了。

## 后果

- **schema 保持可读。** 字段的位置说明它是干什么用的；没有任何东西因为「来得晚」而待在尾部。
- **不必为每次重建写 ADR。** 真实使用之前的记忆核心重生成语料，是提交里的一行说明，不是一份
  迁移设计。
- **陈旧的 store 永远不会被悄悄重新解释。** 号不同，旧 payload 要么被版本检查拒绝，要么落在
  解码器的默认值上、由它的主人看出来——诚实的指示始终是「用写下它的那版构建导出，或者删掉它」。
- **代价落在真正需要兼容的人头上**，而且落成一条**写下来的**要求，付账方式是导出导入工具或
  引擎自己的格式，从来不是 codec 的意外性质。
- **升级是一件事务部署形态，不是 codec 功能。** 蓝绿加一个短切换停机；那固定存在的秒级停机是
  单写 store 的价钱——被排进窗口、被网关重试兜住、被用户吞掉，而不是在 payload 里绕开它。
