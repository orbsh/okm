# 0073 — 最不适配的那个引擎是夹具，不是后端

状态：2026-11-20 裁决，按现状生效。

## 背景

ADR-0010 引入 slatedb，是为了一个已经不存在的部署形态：SST 放在对象存储里、自带 WAL 与自己的 flush 节奏。存储现在只留本地路径，slatedb 于是没有生产位置；顺手跟着那个形态一起删掉是最自然的动作。

但删掉之后，`VirtualStorage` 就只剩 fjall 与 redb 两个引擎在测——两个几乎处处一致的嵌入式引擎：本地文件、同步 API、前缀压缩的块、一个测试可以随手写出范围扫描的接口。只被「意见一致」的引擎测过的契约，不叫被测过，叫做被举例过。

slatedb 就是那个不一致。它是异步的，被 `SlatedbSync` 用线程上的一个运行时桥回同步契约（一次调用一个回复）；持久化是对象存储，有自己的 WAL 与 flush 间隔；压缩按自己的节奏做；扫描交回的是它自己的 owned 迭代器，core 只能当 `ScanIter::External` 拿着。这些摩擦是量出来的，不是推想的：等持久化的 `put` 要等下一次 flush，默认 100 ms——实测 101 ms/put，平的，与数据量无关（ADR-0059）。

## 决定

1. **slatedb 留着，作为一致性夹具。** 它不是受支持的部署后端，也不按后端宣传：要部署 okm 的构建不开这个 feature。它的用处恰好与部署相反——当某个测试假设了 fjall 的行为时，它是会失败的那个引擎。
2. **它留在矩阵里，作为自己的一个 arm。** `TestStore::matrix()` 保留 `slatedb-mem`，CI 的 `--all-features` 任务要跑到它。没人跑的夹具是装饰。
3. **便宜的那个默认值从它身上移走。** `EphemeralStore` 落进 core 之后，测试的零文件系统默认引擎换成没有运行时、没有异步桥的那个，日常那一档保持便宜，slatedb 的 arm 变成显式。在它落地之前，`slatedb-mem` 仍是默认。
4. **测试写在 trait 上，不写在夹具上。** 只有当整套测试向 `VirtualStorage` 提问时，这个 arm 才算证据；给 slatedb 开特例的测试，把对照组变成装饰。

## 由此而来

- `okm-core` 的 dev-dependency 继续开 `slatedb`，这就是对照组的价格：测试构建里有 tokio。发布构建里没有——CI 里那条拒绝 `okm-core/src` 出现 `tokio`/`slatedb` 的闸门保留。
- README 的引擎清单要写明 slatedb 是干什么用的，免得被读成一个可选项。
- ADR-0010 的远端形态没了，但它的抽象仍有反例，这正是 `VirtualStorage` 可以继续是 trait、而不坍缩成 fjall 的理由。

## 被否

- **跟着远端形态一起删掉 slatedb。** 两个一致的引擎无法否证一个抽象；矩阵里唯一能当反例的就是那个不一致的。
- **把它重新提升为部署后端。** 存储只留本地路径，而对象存储这个形态本身也是 ADR-0056 明确拒绝给日志用的。
