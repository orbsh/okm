# Key 布局：ns 前缀与 slot 分派

> **Languages:** [English](key-layout.md) (primary) · [中文](key-layout.zh-CN.md)

本文是机制与实现细节文档：所有落进 engine 的 key 的第一级布局——2 字节 ns 前缀怎么编码、文档与关系表怎么共用这一级、slot 怎么接在后面。slot 的分配纪律与 append-only 契约见[slot 机制](slot-mechanism.zh-CN.md)；决策记录见 [ADR-0002](../adr/0002-namespace-dictionary.md)、[ADR-0005](../adr/0005-secondary-index-slots.md)、[ADR-0016](../adr/0016-four-byte-head-and-slot-segments.zh-CN.md)（条目头，其固定面部分已被取代）、[ADR-0030](../adr/0030-slot-fixed-faces-and-counting-families.zh-CN.md)——现行分配：固定面一字节，计数族保留 2 字节 slot。

## 声明位置：ns 挂在文档上，不挂在 Key 上

`#[ok_ns(N)]` 声明在 **document struct** 上，不在 key struct 上：

- document 是集合的声明点——它的 `#[ok_ref]` 已把 key 类型钉死，`Collection<S, K, R>` 三个参数由 document 完全决定，ns 是这个集合的身份的一部分；
- key 类型不带 ns，意味着**同一个 key 形状可以合法服务多个 document / 多个集合**，各挂各的 ns 号。若 ns 挂 key，这个场景被编译期堵死，只能靠多声明一份同构 key 类型绕行。

derive（`okm-derive`）把 `#[ok_ns(N)]` 编译成 `Document::NS_PREFIX: &'static [u8]`（大端 `[hi, lo]` 两字节，未声明 = 空切片，对应仅做 codec、不落表的 document）。`Collection::open(store)` 不收 ns 参数——拼装点只选 engine，不复述 ns（ns 词汇表是代码，ADR-0002；engine 选择是每拼装点的自由，ADR-0010）。

关系表自己声明 ns，和任何集合一样（ADR-0051）：那对身份就是键，反向方向是同一个 ns 里的一条声明索引。没有 junction 段，也没有双 ns 寄生要推理。

## 第一级：2 字节 ns 前缀，所有条目共用

所有条目的 key 都以同构的 2 字节 BE 头开头——ns 原值大端写入，文档、索引、reduce 共用完整的 16 位编号空间，无变换、无保留半区：

```text
[ ns 2B BE ] ...
```

## 第二级：slot——固定面一字节，计数族两字节

ns 头之后是 slot。它的首字节自己说明后面还跟不跟计数字节：

```text
固定面        首字节 < 0x20          slot = 1 字节   [ns][0x1F]
计数族        首字节 ≥ 0x20          slot = 2 字节   [ns][0x2n][nn]
                                                    计数 = (n << 8) | nn
```

**固定面**（1 字节）——一族只有一张面，没有可枚举的东西。大端是"高位在左"的原因，也是这条定界成立的原因：0x00–0x1F 永远不可能等于计数族的首字节（≥ 0x20）。

**三十二张固定面：自 `0x00` 起紧排，留一块储备，助记符在带尾。** 核心结构占 `0x00`–`0x0F`（三本词汇表、图的四面、簇的六面：kind 词表两个方向、簇行、两张成员面与两张派生面），图的句柄登记册占 `0x10`/`0x11`，点簇的两张面 `0x12`/`0x13`，`0x14`–`0x1D` 是**一整块**未分配的头寸——全带唯一的储备——带尾留给两个助记符：Extension 在 `0x1E`，表元信息在 `0x1F`。带子从零紧排，所以永远不需要为了腾位置给谁改号：下一张面直接拿 `0x14`，也就是储备的底部。`0x1F` 故意坐在最高号上：`slot <= 0x1F` 正是单字节／两字节的定界判据，元信息因此恰好坐在边界上，后来新增的面永远挤不掉它；计数族从 `0x2nnn` 起，是对称的同一个理由——族 `0x1` 会编码成 `0x10nn`–`0x1Fnn`，而它的首字节是一张固定面。

固定面表不在这里重复。每张面的号码、键形状、值宽度，以及三个词表各自的 id 宽度和句柄宽度，都定义在 `okm-core/src/model/layout.rs`：那是引擎里唯一写下这些数字的地方，ADR-0030 记的是产生那张表的规则。本文只讲两条机制层面的判据——固定面一字节、计数族两字节，以及 `0x00`–`0x1F` 与 `0x2nnn` 起这两个端点为什么这么定。

图键里的端点是一个**句柄**——八字节，图自己的编号，不是一段引用。所以每条遍历行都是定宽：`[src_h 8][pred 2][dst_h 8]`，每张图、每条边都十八字节，不管成员表的键是四字节还是十六字节。句柄代表的 `(ns, pkey)` 住在登记册的两张面 `0x10`/`0x11` 上，只在使用方要回引用时才读（见[图自己的句柄空间](#图自己的句柄空间两张面)），所以遍历键里没有任何变长段，解析它也不需要查成员表的声明宽度。端点 ns 不在图的声明里，写入期仍然报 `Error::ForeignEndpoint`——这道检查挪到了发句柄的地方，没有消失。

`0x0D` 与 `0x0F` 在各自的段之后带的是同一行十八字节：`0x0D` 以 `(kind, 簇号)` 领衔、行在第二段，`0x0F` 以行领衔、`(kind, 簇号)` 在第二段，于是一张面按簇有序、另一张按边有序。这对面存在两次的全部理由就是这个。

边**没有号**（ADR-0067）。它的身份就是元组 `(src, pred, dst)`，`0x06` **就是**边这一行——值即载荷——边**不写** `0x00` 行。`0x07`/`0x08`/`0x09` 是由它派生的镜像空面，谓词（两字节）在四张面里都有，所以 `0x08` 的裸 `[pred]` 前缀就是谓词索引。

**计数族**（2 字节，12 位计数，从 `0x2` 起按声明序向上编号）——族内实例按声明序或区分号枚举：

```text
0x2nnn  词表：label → id   [ns][0x2nnn][label 字节]         nnn = 词表自己的编号
0x3nnn  词表：id → label   [ns][0x3nnn][id BE 字节]         同一个 nnn
                                                          （游标在它的裸前缀上）
0x4nnn  声明索引           [ns][0x4nnn][索引字段][主键前缀]   nnn = 声明序
0x5nnn  reduce             [ns][0x5nnn][group 段]            nnn = 声明序，独立计数器
0x6nnn  前导面               [ns][0x6nnn][键字段段][主键前缀]  计数 = 声明序
                            （ADR-0054：段取自键自己的编码）
段 0x7–0xF                 空着
```

一个声明的 `Vocab<N>` 字段（ADR-0032）只花**一个**编号：0x2nnn / 0x3nnn 是它的两个方向。
方向住在族号里，绝不靠族内奇偶约定——`0x2001`/`0x3001` 是第一个分类字段的
label → id / id → label 两面，`0x2002`/`0x3002` 是第二个。label 方向是这对里**低**的那个，
因为两个方向就是同一条声明读两次，而族空间是从底部往上填的：label、id、索引、reduce、
前导面。布局变更是迁移，所以从来不存在需要绕开的旧编号。**面级单值（face-level singleton）。** 一张面可以放**一个**元数据值，键就是裸面前缀
`[ns][slot]`，不带任何后缀。成立的条件很硬：该面所有真实条目的后缀长度恒 ≥ 1——于是零长度
后缀在编码层面无法产生，两者靠**结构**不可能相撞，不靠"保留某个值"。词表的分配游标就是
第一个这样的值（`[ns][0x3nnn] → 下一个 id`）：id 面合格，因为真实条目恒为 N 字节；label 面
不合格，因为空串是合法标签——所以游标放在 id 那一侧。读者判断"是数据还是单值"只看长度，
而定宽解码器本来就会拒绝长度不符的后缀，于是单值解不出任何 id。reduce 面不能放：无分组模式下
它的条目键**就是**裸前缀。

两个 collection 级的名称域早于此
方案，继续留在固定面（0x02/0x03 字段名、0x04/0x05 谓词 token）——**它们也各有一条游标**，形状完全一样：
`[ns][0x02]` 与 `[ns][0x04]` 存的都是本对词汇表的下一个 id。枚举型读者不用特判就能跳过它们，
因为它们本来就按后缀宽度过滤。

**游标键是推导出来的，而这属于导出契约。** 它不自带编号：就是 ID 面的编号、后面一个 id 字节都不跟。
所以导出的 schema 只列每对词汇表的两张面、不提游标——宿主侧的写入方（回放 plan 的远程绑定、自行分配 id 的
语言绑定）用 `obj_vocab::cursor_key` 从 id 面号拼出键，读条目拿下一个 id，并在**同一个 commit** 里
把递增后的值连同花掉它的那些条目一起写下去。这个同批耦合就是要害：不读游标就分配、或写了条目不写
游标，都会发出 store 已经用过的 id，而键布局本身抓不住——它只会在之后表现为某个标签解析成了别的名字。

宽度规则是关于字节的事实（`b < 0x20` 读 1 字节 slot，否则读 2 字节），不是查一张要维护的表——与下文的 ns 转义字节同一立场。所以按族拼前缀扫描天然精确，不需要查任何东西：`[ns][0x07]` 不可能命中计数族，`[ns][0x2n][nn]` 不可能命中固定面。迭代也不需要自带上界：前缀扫描止于前缀的字节序后继，因此走不进相邻的面——一字节/两字节的接缝也一样（ADR-0033）。

每族的计数容量是 4096：声明索引与 reduce 占 1–4095（0 保留）。多对多关系不需要自己的计数：它是一张集合，正向是主键前缀，反向是该集合 0x4nnn 里的一条声明索引。

slot 让"集合内加派生数据"永不侵占相邻集合的 ns 段（ADR-0005），而且它的首字节在两种形态下都是结构事实：既界定 slot 又给出族名，固定面号不可能被误读成族号。被取代的段表（所有条目统一的 4 bit 段号 + 12 bit 计数）见 [ADR-0016](../adr/0016-four-byte-head-and-slot-segments.zh-CN.md)。分配纪律、append-only 契约、变长字段的约束见[slot 机制](slot-mechanism.zh-CN.md)。

## 布局版本：变更即迁移

上面这些编号是**当前**布局，除此之外没有任何人读它们。布局变更——面挪位、族重新编号、键段改形——是在这张表自己的地址上做一次**迁移**（ADR-0075）：代际的奇偶是 ns 的首位，于是两代在同一个库里是两个区间，谁也不为谁再造第二份。旧区间照旧服务读，`okm-log migrate` 用旧声明解它、用新声明写回去，然后翻转这张表的记录，`okm-log vacuum` 之后退役旧区间。声明的 `layout_version` 随变更递增——递增一，因为隔开两个区间的正是奇偶——用别的号盖章的 store 会被**拒绝**而不是半读：读方对不认识的布局去猜，等于把版本不符变成悄悄写错的行。另一个跨版本契约是**导出格式**：它自带版本，由对应版本的导入器来读，所以数据是经由导出器（而不是经由读方）到达另一个 store 的。

**partition 前缀（可选，在 ns 头之前）**：`#[ok_partition(N)]` 声明的集合，所有键在最前面多一段 `[0xFF][N 1B]`：

```text
partition 条目  [ 0xFF ][ part 1B ][ ns 2B ][ slot … ][ ... ]
```

`0xFF` 是转义字节——合法 ns 头（大端 u16，首字节受 ns 词汇表纪律约束为 0x00–0xFE）永不以它开头，所以 partition 集合与普通集合的键空间**结构性不相交**，无需任何编号协调（partition(0) 非法——直接省略属性即无段）。语义：partition 是 workload 隔离（compaction 分组），不是所有权边界；ns 仍是归属的最外层。

## 面级单值：键比它的子行短的几种行

  有些值不属于任何一个条目，它属于**一张面**。落法是让它的键比同面的条目短——极端情况就是裸面前缀：

```text
[ns][0x02]              → 词表分配游标（同面 0x02 底下是 [ns][0x02][id] 条目）  ← 69197cd
[ns][0x04]              → 谓词游标（同形状）
[ns][0x0C][kind][簇号]  → 簇行（成员在 0x0D，子簇在 0x0E）
[ns][0x10]              → 图句柄游标（条目在 [ns][0x10][handle 8]）
[ns][0x1F]              → 表元信息（底下没有子行）
```

  读法只有一条，**看键长**：长度恰好是该行型的定长就是值，更长的是条目。但在用它之前要先问一句"子行在同一个面里吗"，因为这决定这条规则是必需还是多余：

- **子行同面**（词表游标）：游标键是每条条目的前缀，按 id 面扫必须限定键长，否则游标会被当成条目读出来；这也是导出 schema 只列两面、不提游标的原因——游标键是推导出来的。
- **子行在别的面**（簇簇行）：面前缀不同，天生不相撞，扫描不需要任何长度判断；代价是"组 + 成员"要两次扫描，而不是一次。

  所以这四种行共用"短键"这个落法，只有第一种需要那条长度规则。那条规则的开销也要说准：**每次扫描一次，不是每行一次**——游标键是一张面的前缀，在字节序上永远排在第一个，读者扫到第一个比一下长度跳过即可。要把它彻底消掉只有两条路：让游标离开这张面（进 Extension 的一个子类），或者让条目扫描从 `[ns][0x02][0x01]` 起扫（前提是 id 0 保留不用）——两者都是省一次比较，换的却是键空间的约定，所以没做。

## 图自己的句柄空间：两张面

```text
0x10  句柄 → 节点   [ns][0x10][handle 8]           → [node_ns 2B][pkey]
0x11  节点 → 句柄   [ns][0x11][node_ns 2B][pkey]   → [handle 8 BE]
```

两张都是**固定面**——各一个字节，没有计数、键里没有任何区分字节——而且相邻：正向面的扫描区间正好止于反向面的起点，"每个方向一行、一个登记册"因此在键空间里是看得见的。它们紧贴在核心（`0x00`–`0x0F`）之后，因为带子自 `0x00` 紧排：这一对拿的是带尾原先那两个号（Extension 与元信息搬到了 `0x1E`/`0x1F`），而全带唯一的储备（`0x14`–`0x1D`）在它们上面。

带子加宽之前它们是**一个**计数族（`0xF00n`，方向放在计数位里），因为十六张固定面已经用光、而它们当时根本不可编码。三十二张面让这一对变得付得起：不占族号、不要区分号，而且相邻是事实而不是数字巧合。

`0x10` 是权威——它存 `(ns, pkey)` 这一对，图的键空间里没有别处再存。`0x11` 由它派生、也只靠它就能重建（`Handles::rebuild_reverse`），所以反向行缺失是新鲜度问题，从来不是正确性问题，修复也不需要任何遍历键。

分配游标是**正向面**上的面级单值：`[ns][0x10]` 不带后缀，与词汇表游标同形，成立的理由也相同——该面所有真实条目的后缀恰是八字节，零长度后缀在编码层面无法产生，八字节解码器会拒绝游标而不是从中读出一个句柄。游标缺失的登记册只回退**一次**到"已发出的最大句柄 + 1"（正向面一次扫描）；这个回退不可能重发活着的句柄，游标一写下去就再也走不到。

生命周期：一个句柄在某个节点第一次作为边的**端点**出现时发出，从 `1` 起单调（`0` 是永不发出的 `Handle::NONE`），此后永不复用。删除不回收：活得比最后一条边久的句柄就是浪费，而回收它意味着引用计数——这个模型没有的资源。浪费的上界是"曾经有过边的节点数"，2^64 让它成为空间问题而不是正确性问题。发出顺序不是键顺序——按句柄取区间等于按"这个节点第一次出现的时间"取区间——所以任何面都不能把句柄区间当成值序。

解析只发生在边界。`Graph::node` 取一个句柄（一次点查），`Graph::nodes` 取一组有序句柄（一次区间扫描，从首跨到尾，所以稀疏集合为跨度付费），`Graph::edge_row` 把一行存下的行身份还原成完整元组。遍历从不解析：一条条目的两个句柄、谓词、远端点，全部来自已经读到的那把键。这就是这套布局做的交换——每跳十八字节定宽、零次读，而想要引用的使用方只为它真正要问的那个集合付一次扫描。

## 全景

```text
document  [ (0xFF part 1B) ][ ns 2B ][ slot 1B（固定面）   ][ ... ]
document  [ (0xFF part 1B) ][ ns 2B ][ slot 2B（计数族）   ][ ... ]
关系表  [ ns 2B            ][ 0x00   ][ A 身份 ][ B 身份 ]         这对身份就是键
关系表  [ ns 2B            ][ 0x4nnn ][ B 身份 ][ A 身份 ]         它的反向，一条声明索引
            ↑ 同一编号空间、同一头纪律；slot 首字节既界定宽度也给出族名——无变换
```

## reduce 的位置

reduce 条目没有独立 ns——它寄生在宿主文档的 ns 段里，计数族 `0x5`，计数器独立于索引：

```text
reduce 条目  [ ns 2B ][ 0x5nnn ][ group 段 ]   value = acc 编码
```

对扫描而言，一个 ns 段内的前缀完整枚举了这张文档的所有派生状态：固定面 0x00–0x03（主表、动态段、字段名词汇表两个方向），然后是计数族：0x2/0x3 两本词汇表的两个方向、0x4 索引、0x5 reduce、0x6 前导面。图（边集合）另加它自己的固定面：谓词词汇表 0x04/0x05（它的谓词）、0x06–0x09（出入边与两面向谓词的面，每面都带着**两端**的句柄——`0x06` 就是边行本身，谓词索引是 0x08 的裸前缀扫描，不再独占一面）、0x0A–0x0F（簇类型词表、簇行、边成员与两张派生面）、0x10/0x11（句柄登记册——图的键空间里唯一还留着 `(ns, pkey)` 的地方）以及 0x12/0x13（点簇的成员面与镜像）。带 kind token 的文档集合声明同一对词汇表——同一条规则，谁需要谁用。机制见[reduce 机制](reduce-mechanism.zh-CN.md)。
