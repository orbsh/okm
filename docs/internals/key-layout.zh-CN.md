# Key 布局：ns 前缀与 slot 分派

本文是机制与实现细节文档：所有落进 engine 的 key 的第一级布局——2 字节 ns 前缀怎么编码、文档与关系表怎么共用这一级、slot 怎么接在后面。slot 的分配纪律与 append-only 契约见[slot 机制](slot-mechanism.zh-CN.md)；决策记录见 [ADR-0002](../adr/0002-namespace-dictionary.md)、[ADR-0005](../adr/0005-secondary-index-slots.md)、[ADR-0016](../adr/0016-four-byte-head-and-slot-segments.zh-CN.md)（条目头，其固定面部分已被取代）、[ADR-0030](../adr/0030-slot-fixed-faces-and-counting-families.zh-CN.md)——现行分配：固定面一字节，计数族保留 2 字节 slot。

## 声明位置：ns 挂在文档上，不挂在 Key 上

`#[ok_ns(N)]` 声明在 **document struct** 上，不在 key struct 上：

- document 是集合的声明点——它的 `#[ok_ref]` 已把 key 类型钉死，`Collection<S, K, R>` 三个参数由 document 完全决定，ns 是这个集合的身份的一部分；
- key 类型不带 ns，意味着**同一个 key 形状可以合法服务多个 document / 多个集合**，各挂各的 ns 号。若 ns 挂 key，这个场景被编译期堵死，只能靠多声明一份同构 key 类型绕行。

derive（`okm-derive`）把 `#[ok_ns(N)]` 编译成 `Document::NS_PREFIX: &'static [u8]`（大端 `[hi, lo]` 两字节，未声明 = 空切片，对应仅做 codec、不落表的 document）。`Collection::new(store)` 不收 ns 参数——拼装点只选 engine，不复述 ns（ns 词汇表是代码，ADR-0002；engine 选择是每拼装点的自由，ADR-0010）。

关系表自己声明 ns，和任何集合一样（ADR-0051）：那对身份就是键，反向方向是同一个 ns 里的一条声明索引。没有 junction 段，也没有双 ns 寄生要推理。

## 第一级：2 字节 ns 前缀，所有条目共用

所有条目的 key 都以同构的 2 字节 BE 头开头——ns 原值大端写入，文档、索引、reduce 共用完整的 16 位编号空间，无变换、无保留半区：

```text
[ ns 2B BE ] ...
```

## 第二级：slot——固定面一字节，计数族两字节

ns 头之后是 slot。它的首字节自己说明后面还跟不跟计数字节：

```text
固定面        首字节高半字节 = 0     slot = 1 字节   [ns][0x0F]
计数族        首字节高半字节 ≠ 0     slot = 2 字节   [ns][0x1n][nn]
                                                    计数 = (n << 8) | nn
```

**固定面**（1 字节，16 个号，现用 14 个；排法：核心结构占 0x00–0x0B；`0x0E` 是 Extension，带内用一个子类字节细分；`0x0F` 坐在定界位上）——一族只有一张面，没有可枚举的东西。大端是"高半字节在左"的原因，也是这条定界成立的原因：0x00–0x0F 永远不可能等于计数族的首字节（≥ 0x10）。

```text
0x00  主表              [ns][0x00][主键]                             value = TLV payload
0x01  obj 动态段        [ns][0x01][主键]                             value = toc_len | blocks | values（[动态段](dynamic-segment.zh-CN.md)）
0x02  字段名词汇表      [ns][0x02][field-id]                         → 名字
0x03  字段名词汇表      [ns][0x03][名字]                             → field-id
0x04  谓词词汇表        [ns][0x04][predicate_id]                     → 谓词名
0x05  谓词词汇表        [ns][0x05][谓词名]                           → predicate_id
0x06  图 出边           [ns][0x06][src 引用][dst 引用][edge_id]
0x07  图 入边           [ns][0x07][dst 引用][src 引用][edge_id]
0x08  图 谓词+出        [ns][0x08][predicate_id][src 引用][dst 引用][edge_id]
0x09  图 谓词+入        [ns][0x09][predicate_id][dst 引用][src 引用][edge_id]
0x0A  超边 组行         [ns][0x0A][kind][组号]                 → [parent_id u64][动态载荷]（成员数/权重/最近写入）
0x0B  超边 边成员       [ns][0x0B][kind][组号][边号]           → 空
0x0C  超边 节点成员     [ns][0x0C][kind][组号][节点][边号]     → 空，从 0x0B 派生可重建
0x0D                        空闲，下一个核心行型从这里取号
0x0E  Extension          [ns][0x0E][子类]…                    子类 0x01 = 向量索引快照（可丢缓存）
0x0F  表元信息         [ns][0x0F]                  → 名字 → 字节的值对（ADR-0043）
（表按角色排：两本词汇表在前，读它们编号的图面在后——词汇表排在它服务的面之前；编号才是机制。
0x0F 是**最高**的固定面，这是故意的：`slot <= 0x0F` 正是单字节／两字节的定界判据，元信息因此
坐在边界上，后来新增的面永远挤不掉它。）
```

**计数族**（2 字节，12 位计数，号码不变）——族内实例按声明序或区分号枚举：

```text
0x1nnn  词表：label → id   [ns][0x1nnn][label 字节]        nnn = 词表自己的编号
0x2nnn  词表：id → label   [ns][0x2nnn][id BE 字节]        同一个 nnn，另一个族
                                                          （游标在它的裸前缀上）
0x3nnn  声明索引           [ns][0x3nnn][索引字段][主键前缀]   nnn = 声明序
0x4nnn  reduce             [ns][0x4nnn][group 段]            nnn = 声明序，独立计数器
0x5nnn  前导面               [ns][0x5nnn][键字段段][主键前缀]  计数 = 声明序
                            （ADR-0054：段取自键自己的编码）
段 0x6–0x0F                空着
```

一个声明的 `Vocab<N>` 字段（ADR-0032）只花**一个**编号：0x1nnn / 0x2nnn 是它的两个方向。
方向住在族号里，绝不靠族内奇偶约定——`0x1001`/`0x2001` 是第一个分类字段的
label → id / id → label 两面，`0x1002`/`0x2002` 是第二个。**面级单值（face-level singleton）。** 一张面可以放**一个**元数据值，键就是裸面前缀
`[ns][slot]`，不带任何后缀。成立的条件很硬：该面所有真实条目的后缀长度恒 ≥ 1——于是零长度
后缀在编码层面无法产生，两者靠**结构**不可能相撞，不靠"保留某个值"。词表的分配游标就是
第一个这样的值（`[ns][0x2nnn] → 下一个 id`）：id 面合格，因为真实条目恒为 N 字节；label 面
不合格，因为空串是合法标签——所以游标放在 id 那一侧。读者判断"是数据还是单值"只看长度，
而定宽解码器本来就会拒绝长度不符的后缀，于是单值解不出任何 id。reduce 面不能放：无分组模式下
它的条目键**就是**裸前缀。

两个 collection 级的名称域早于此
方案，继续留在固定面（0x02/0x03 字段名、0x04/0x05 谓词 token）——**它们也各有一条游标**，形状完全一样：
`[ns][0x02]` 与 `[ns][0x04]` 存的都是本对词汇表的下一个 id。枚举型读者不用特判就能跳过它们，
因为它们本来就按后缀宽度过滤。

**游标键是推导出来的，而这属于导出契约。** 它不自带编号：就是 ID 面的编号、后面一个 id 字节都不跟。
所以导出的 schema 只列每对词汇表的两张面、不提游标——宿主侧的写入方（回放 plan 的远程绑定、自行分配 id 的
语言绑定）用 `obj_vocab::cursor_key` 从 id 面号拼出键，读条目拿下一个 id，并在**同一个 commit** 里
把递增后的值连同花掉它的那些条目一起写下去。这个同批耦合就是要害：不读游标就分配、或写了条目不写
游标，都会发出 store 已经用过的 id，而键布局本身抓不住——它只会在之后表现为某个标签解析成了别的名字。

宽度规则是关于字节的事实（`b & 0xF0 == 0` 读 1 字节 slot，否则读 2 字节），不是查一张要维护的表——与下文的 ns 转义字节、以及自描述端点引用（ADR-0017 §2）同一立场。所以按族拼前缀扫描天然精确，不需要查任何东西：`[ns][0x07]` 不可能命中计数族，`[ns][0x1n][nn]` 不可能命中固定面。迭代也不需要自带上界：前缀扫描止于前缀的字节序后继，因此走不进相邻的面——一字节/两字节的接缝也一样（ADR-0033）。

每族的计数容量是 4096：声明索引与 reduce 占 1–4095（0 保留）。多对多关系不需要自己的计数：它是一张集合，正向是主键前缀，反向是该集合 0x3nnn 里的一条声明索引。

slot 让"集合内加派生数据"永不侵占相邻集合的 ns 段（ADR-0005），而且它的首字节在两种形态下都是结构事实：既界定 slot 又给出族名，固定面号不可能被误读成族号。被取代的段表（所有条目统一的 4 bit 段号 + 12 bit 计数）见 [ADR-0016](../adr/0016-four-byte-head-and-slot-segments.zh-CN.md)。分配纪律、append-only 契约、变长字段的约束见[slot 机制](slot-mechanism.zh-CN.md)。

**partition 前缀（可选，在 ns 头之前）**：`#[ok_partition(N)]` 声明的集合，所有键在最前面多一段 `[0xFF][N 1B]`：

```text
partition 条目  [ 0xFF ][ part 1B ][ ns 2B ][ slot … ][ ... ]
```

`0xFF` 是转义字节——合法 ns 头（大端 u16，首字节受 ns 词汇表纪律约束为 0x00–0xFE）永不以它开头，所以 partition 集合与普通集合的键空间**结构性不相交**，无需任何编号协调（partition(0) 非法——直接省略属性即无段）。语义：partition 是 workload 隔离（compaction 分组），不是所有权边界；ns 仍是归属的最外层。

## 面级单值：键比它的子行短的几种行

  有些值不属于任何一个条目，它属于**一张面**。落法是让它的键比同面的条目短——极端情况就是裸面前缀：

```text
[ns][0x02]              → 词表分配游标（同面 0x02 底下是 [ns][0x02][id] 条目）  ← 69197cd
[ns][0x04]              → 谓词游标（同形状）
[ns][0x0A][kind][组号]  → 超边组行（成员在 0x0B/0x0C，别的面）
[ns][0x0F]              → 表元信息（底下没有子行）
```

  读法只有一条，**看键长**：长度恰好是该行型的定长就是值，更长的是条目。但在用它之前要先问一句"子行在同一个面里吗"，因为这决定这条规则是必需还是多余：

- **子行同面**（词表游标）：游标键是每条条目的前缀，按 id 面扫必须限定键长，否则游标会被当成条目读出来；这也是导出 schema 只列两面、不提游标的原因——游标键是推导出来的。
- **子行在别的面**（超边组行）：面前缀不同，天生不相撞，扫描不需要任何长度判断；代价是"组 + 成员"要两次扫描，而不是一次。

  所以这四种行共用"短键"这个落法，只有第一种需要那条长度规则。

## 全景

```text
document  [ (0xFF part 1B) ][ ns 2B ][ slot 1B（固定面）   ][ ... ]
document  [ (0xFF part 1B) ][ ns 2B ][ slot 2B（计数族）   ][ ... ]
关系表  [ ns 2B            ][ 0x00   ][ A 身份 ][ B 身份 ]         这对身份就是键
关系表  [ ns 2B            ][ 0x3nnn ][ B 身份 ][ A 身份 ]         它的反向，一条声明索引
            ↑ 同一编号空间、同一头纪律；slot 首字节既界定宽度也给出族名——无变换
```

## reduce 的位置

reduce 条目没有独立 ns——它寄生在宿主文档的 ns 段里，段 0x4，计数器独立于索引：

```text
reduce 条目  [ ns 2B ][ 0x4nnn ][ group 段 ]   value = acc 编码
```

对扫描而言，一个 ns 段内的前缀完整枚举了这张文档的所有派生状态：固定面 0x00–0x03（主表、动态段、字段名词汇表两个方向），然后是计数族 0x1 词汇表、0x3 索引、0x4 reduce。图（边集合）另加它自己的固定面：谓词词汇表 0x04/0x05（它的谓词）与 0x06–0x09（出入边与两面向谓词的面，每面都带着**两端**——谓词索引是 0x08 的裸前缀扫描，不再独占一面）。带 kind token 的文档集合声明同一对词汇表——同一条规则，谁需要谁用。机制见[reduce 机制](reduce-mechanism.zh-CN.md)。
